# Матрица видимости клиентских кабинетов (ТЗ §3.2 + §7)

Дата аудита: 2026-07-27 · Этап 10 ТЗ (PR-1 + PR-2) · Спека:
[2026-07-27-stage10-visibility-audit-design.md](../superpowers/specs/2026-07-27-stage10-visibility-audit-design.md)

**Живой артефакт.** Новая клиентская поверхность (API-роут, server-action,
страница кабинета, читающая `prisma` напрямую) обязана попасть в эту таблицу.

**Вердикты:** `ok` — наружу уходит ровно то, что должно · `over-fetch` — из БД
тянется лишнее, но наружу не уходит (нарушение буквы §7: «select-ами, не
пост-фильтрацией») · `leak` — внутреннее поле уходит клиенту · `удалено` —
поверхность убрана этим этапом.

## 1. Домен лидов — удалён из клиентского контура

Решение заказчика 27.07.2026: «партнёр вообще не должен видеть лидов и
организация тоже, это только внутренний процесс» (= §3.2 ТЗ).

| Поверхность | Было | Стало |
|---|---|---|
| `GET/POST /api/partner/leads` | отдавал список лидов партнёра | **удалено** |
| `GET/PATCH /api/partner/leads/[id]` | **leak**: `assignedManagerName` (§7 запрещает), `notes` (двусмысленное поле) | **удалено** |
| `/api/partner/leads/[id]/attachments*` (3 роута) | вложения лида | **удалено** |
| `/partner/leads`, `/partner/leads/[id]`, `/partner/leads/new` | экраны лидов (UI уже редиректил с этапа 5, **API оставался открыт**) | **удалено** |
| `services/partner/leads.ts`, `leadAttachments.ts` | `include` всей записи `Lead` + отбрасывание в JS | **удалено** |
| KPI «Заявки в работе», блок «Залежавшиеся лиды», события `lead_created` на дашборде партнёра | показывали внутреннюю воронку | **удалено** |
| Уведомление `lead_status_changed` партнёру | раскрывало внутренние стадии («Квалифицирована», «Передана в сделку») | **удалено** (enum-значение в БД оставлено, продьюсеров нет) |
| Флаг `partner_leads`, пункт меню «Заявки», мобильная вкладка | точки входа в домен | **удалено** (мобильная вкладка → «Обращения») |

Клиентский канал подачи остаётся один — **обращения** (`ClientRequest`, этап 5):
клиент видит свою заявку и её статус, но не внутренний лид, в который она
превратилась.

## 3. Чувствительное соседство

`getOrgIntermediaryCommissionForOrgs` (комиссия посредника, помечена «Sensitive
— callers MUST gate this to admin/leader») физически лежит в
`services/**organization**/finance.ts` — рядом с функциями, которые импортирует
клиентская страница финансов. Вызывающий сегодня один и корректный
(`manager/finance.ts`), но расположение провоцировало ошибку.
**Исправлено (PR-2):** сервис вынесен в `services/manager/orgCommission.ts`,
компонент — в `components/manager/org-finance-commission.tsx`. В клиентском
неймспейсе расчёта комиссии больше нет.
