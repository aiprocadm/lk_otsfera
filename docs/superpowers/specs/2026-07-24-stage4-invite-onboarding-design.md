# Этап 4 ТЗ — онбординг по приглашению (Модуль 10, ФТ-10.1–10.4)

Дата: 2026-07-24 · Статус: **ждёт подтверждения заказчика** (вопросы §8) ·
ТЗ: [docs/tz/2026-07-23-tz-lk-otsfera-v1.md](../../tz/2026-07-23-tz-lk-otsfera-v1.md) §Модуль 10, §9 этап 4.

## 1. Цель и критерий приёмки (§9 ТЗ)

«Приглашённый получает письмо автоматически, устанавливает пароль по
welcome-странице, видит одноразовый welcome-блок».

## 2. Что уже есть в main (не делаем заново)

- Инвайт-токены: `PasswordResetToken` (`purpose: 'invite' | 'reset'`, sha256,
  TTL 7 дней у инвайта / 2 ч у сброса), `createInviteToken` /
  `verifyAndConsumeToken` в `src/lib/auth/passwordReset.ts`.
- Письма уже шлются: org-команда и org-admin (`sendOrgInviteEmail`),
  админка пользователей/партнёров (`sendAdminUserInviteEmail`), менеджер при
  создании из админки (`sendManagerInviteEmail`). Шаблоны в реестре
  `email/templates/index.ts`, фолбэк-ссылка «Скопировать» в org-форме есть.
- Страница `/reset-password?token=` устанавливает пароль (одна на сброс и
  приглашение), rate-limit на request/confirm.

## 3. Пробелы, которые закрывает этап (по разведке кода)

1. **Команда партнёра** (`partner/team.ts` + `POST /api/partner/team`) —
   единственная точка на «временном пароле» (`randomBytes` → bcrypt): без
   invite-токена, без письма, UI обещает «отправим инструкцию», но не шлёт.
2. **Leader-путь назначения менеджера** (`server-actions/manager/team.ts`) —
   возвращает `inviteUrl`, письмо не шлёт (admin-путь шлёт).
3. **«Отправить письмо повторно»** (ФТ-10.2) — нет ни в одной таблице команд.
4. **Различение приглашение/сброс** (ФТ-10.3) — `purpose` в токене есть, но
   страница и формы его не используют: приглашённый видит «Установка пароля»
   вместо «Добро пожаловать».
5. **Welcome-блок** (ФТ-10.4) — поля на `User` нет, дашборды блока не имеют.

## 4. Дизайн — ФТ-10.1 (письма всюду + фолбэк)

- `partner/team.ts::inviteMember` переводится на общую модель:
  `passwordHash: null` + `createInviteToken` → `{ user, inviteUrl }`; роут
  `/api/partner/team` шлёт новое письмо `sendPartnerInviteEmail` (шаблон
  `PartnerInviteTemplate` по образцу `OrgInviteTemplate`: кто пригласил,
  партнёр, роль, кнопка «Установить пароль», срок действия). UI-форма после
  успеха показывает ссылку + «Скопировать» (как org-форма) — это же фолбэк
  при выключенном email (письмо `skipped` → показываем ссылку с пометкой).
- Leader-путь менеджера: в `leaderAssignManagerAction` добавляется та же
  отправка `sendManagerInviteEmail`, что в admin-пути.
- Все send-вызовы best-effort (§3): сбой письма не ломает приглашение,
  ссылка остаётся видимой пригласившему.
- Временный пароль у партнёрской команды исчезает (вопрос §8-1): уже
  созданные «неактивированные» пользователи со старым временным паролем
  продолжают работать через «Забыли пароль» — миграции не требуется.

## 5. Дизайн — ФТ-10.2 (скопировать / отправить повторно)

- Server-action `resendInviteAction` (per-роль тонкие обёртки над общим
  `resendInvite(prisma, session, { userId })` в `src/lib/services/team/resend.ts`):
  гейты скоупа (org-admin — свой участник; partner-admin — свой; leader/admin —
  свои точки), пользователь должен быть без `passwordHash` и активен;
  старые невыгоревшие инвайт-токены гасятся (`usedAt = now`), выпускается
  новый (7 дней), шлётся то же письмо точки; аудит `invite_resent`.
- UI: в таблицах команд (org, partner) и `/admin/users` у участников без
  пароля — кнопки «Отправить письмо повторно» и «Скопировать ссылку»
  (ссылка возвращается экшеном; показывается в тех же формах-паттернах).
- Rate-limit: 5 повторных отправок в час на приглашающего (существующий
  `isRateLimited`).

## 6. Дизайн — ФТ-10.3 (страница различает приглашение и сброс)

- `/reset-password?token=` серверно читает токен **без погашения** (select по
  sha256-хешу: `purpose`, `usedAt`, `expiresAt`): валидный `invite` →
  заголовок «Добро пожаловать! Придумайте пароль» + подпись «Аккаунт создан
  для вас — осталось установить пароль»; `reset` — текущая «Установка
  пароля»; просроченный/погашенный — существующее сообщение об ошибке.
  `verifyAndConsumeToken` не меняется (invite и reset остаются
  взаимозаменяемыми при погашении — обратная совместимость старых ссылок).

## 7. Дизайн — ФТ-10.4 (одноразовый welcome-блок)

- Миграция: `User.welcomeSeenAt DateTime?` (additive, без потери данных).
- Блок на дашбордах **клиентских ролей** (organization, partner), только пока
  `welcomeSeenAt == null`: приветствие по имени + 3 карточки прямых действий
  (вопрос §8-3): «Подать заявку на обучение» (→ enrollments, при флаге),
  «Удостоверения» (→ certificates, при флаге), «Документы» (→ documents);
  карточки, чей флаг выключен, заменяются на «Заказы»/«Финансы».
- Кнопка «Скрыть» → server-action ставит `welcomeSeenAt = now` (вопрос §8-2);
  sibling-компоненты `org-welcome-card` / `partner-welcome-card`.
- Новый фича-флаг не заводится: блок виден только новым пользователям и
  скрывается ими самими; письма уже гейтятся `email.enabled` (вопрос §8-4).

## 9. Тестовая стратегия (порог 100%)

- partner/team: инвайт-токен вместо temp-пароля, письмо, фолбэк-ссылка
  (unit + integration).
- resendInvite: скоупы всех ролей, гашение старых токенов, rate-limit,
  пользователь с паролем → validation; аудит.
- Страница `/reset-password`: invite/reset/просроченный — заголовки
  (renderServerComponent); токен не гасится показом.
- welcome-блок: виден при `welcomeSeenAt=null`, скрытие, подстановка
  карточек по флагам; dismiss-action.
- Существующие invite/team-тесты обновляются под новую модель партнёра.

## 10. Вне скоупа

- «Задать вопрос» в welcome-блоке (Модуль 11 — этап 9).
- Ревокация сессий, lastLoginAt (Модуль 11 — этап 9).
- Welcome-блок для staff-ролей (ТЗ просит только клиентские).
