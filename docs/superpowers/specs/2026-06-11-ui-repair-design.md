# UI-ремонт перед запуском: сломанные пути и единообразие

**Дата:** 2026-06-11
**Статус:** дизайн утверждён пользователем (brainstorming), ждёт plan
**Источник:** UX-аудит всех кабинетов (живой прогон под 4 ролями + 2 код-агента). Реальных пользователей ещё нет — цель навести логичность и единообразие до запуска.

Связанная спека: [2026-06-11-leader-cabinet-design.md](2026-06-11-leader-cabinet-design.md) — строится **после** этой (зависит от §1 «единый канон навигации»).

## Решения пользователя (зафиксированы)

| Вопрос | Решение |

| Бренд | **«Промтехносфера»** везде (логотип, шапки, title, футер). «ОТСФЕРА» уходит. |

## §1. Навигация — один источник правды

Сейчас три источника: канон [src/lib/navigation/cabinet.ts](../../../src/lib/navigation/cabinet.ts) (используют partner и organization), захардкоженный `GROUPS` в [admin-sidebar.tsx](../../../src/components/admin/admin-sidebar.tsx) и захардкоженный `ITEMS` в [manager-sidebar.tsx](../../../src/components/manager/manager-sidebar.tsx). Последние два молча разъехались с каноном: у менеджера в меню нет «Финансов» (страница есть!), у админа недостижимы 4 страницы (`/admin/orders`, `/admin/documents`, `/admin/messages`, `/admin/finance`), а `navByRole.admin` — мёртвые английские данные.

**Дизайн:**

- `NavItem` расширяется полем `group?: string` (для админских секций «Платформа / Операции / Справочники»); `icon` уже есть.
- `navByRole.admin` переписывается: русские названия, иконки, группы, **все 13 страниц** (Дашборд, Здоровье, Синхронизация / Заказы, Документы, Сообщения, Комиссии, Финансы, Загрузка из 1С, Аудит / Пользователи, Партнёры, Организации).
- `navByRole.manager` дополняется: «Финансы» (`/manager/finance`). «Команда» остаётся `leaderOnly` до выхода кабинета руководителя.
- `AdminSidebar` и `ManagerSidebar` переходят на **items-prop с сервера** (паттерн OrgSidebar из PR #103: серверный shell вызывает `navItemsFor()` и передаёт массив; клиентский компонент только рендерит; импорт типа `NavItem` — type-only, чтобы флаги остались server-side).
- Единые названия пунктов: **«Главная»** (у партнёра «Дашборд» → «Главная», в мобильном меню партнёра «Кабинет» → «Главная»).
- Существующие unit-тесты сайдбаров обновляются и становятся guardrail: сайдбар рендерит ровно то, что отдал канон (защита от нового дрейфа).

## §2. Сломанный выход + мёртвый код входных точек

1. **Выход = голый JSON (реальный баг, подтверждён вживую).** Все четыре шелла рендерят `<form action='/api/auth/logout' method='post'>` — браузер уходит на API-ответ и показывает `{"ok":true}`. Дизайн: общий клиентский `LogoutButton` (`src/components/ui/`): fetch-POST на logout → `router.push('/login')` + `router.refresh()`. Единый текст **«Выйти»** (сейчас «Выход»/«Выйти» вперемешку). Все 4 шелла переводятся на него.
2. **Корень `/` и `/forbidden` — НЕ сломаны** (находка агентов оказалась ложной): middleware уже редиректит `/` и `/dashboard` на `roleHome[role]` ([access.ts](../../../src/lib/auth/access.ts), [middleware.ts:69](../../../src/middleware.ts)). Но опираться на это неочевидно, а в коде лежат ловушки на будущее: [src/app/page.tsx](../../../src/app/page.tsx) хардкодит `redirect('/organization/dashboard')` (мёртвый код, сработает только при изменении middleware-matcher), `/forbidden` и `LoginForm` ссылаются на виртуальный `/dashboard`. Дизайн-минимум: `page.tsx` меняет хардкод на `redirect('/login')` (страховка, согласованная с middleware), комментарий-указатель на middleware; `/forbidden` остаётся на `/dashboard` (работает), но получает комментарий, что `/dashboard` — middleware-алиас. Новую функцию не вводим — канон уже есть (`roleHome`).

## §3. Доверие к цифрам и словам

1. **Статус оплаты против цифр.** Сейчас бейдж «оплачен» берётся из статуса 1С и противоречит расчёту по платежам («Завершена, оплачена» рядом с «Оплачено 0 ₽ · Долг 100 000 ₽»). Правило: **бейдж оплаты выводится из чисел** (`paid >= amount` → «Оплачен», `0 < paid < amount` → «Частично оплачен», `paid = 0` → «Не оплачен»); стадия исполнения («Новый/В работе/Завершён») — отдельный бейдж из статуса 1С. Никогда не показываем «оплачен» при долге > 0.
2. **Род статусов.** После переименования «Сделки»→«Заказы» все человеческие статусы — в мужском роде («Завершён, частично оплачен»); женские формы из `humanStage` уходят.
3. **Словари enum→русский** (один модуль, рядом с `errorMessageRu`): тип заказа (`supply`→«Поставка», `service`→«Услуга»), способ оплаты (`wire`→«Банковский перевод» и остальные), неизвестное значение → показать как есть (не падать).
4. **Ошибки входа по-русски**: «Invalid credentials» → через `errorMessageRu` («Неверный email или пароль»).
5. **Лента событий админа** показывает сырые коды (`commission_statement_approved (commission_statement #cmpsf…)`). Дизайн: словарь action→русская фраза (переиспользовать/расширить словарь страницы Аудита), cuid-ы в тексте не показываем; нет перевода → humanized fallback без id.

## §4. Комиссия — правило видимости

Каноническое правило: **комиссию видят только партнёр (свою), руководитель менеджеров и админ.**

- Из финансов организации удаляется блок «Комиссия посредника» (`OrgFinanceCommission` на `/organization/finance`) и его field-level расчёт для org-зрителей в сервисе (`getOrgIntermediaryCommission` не вызывается для роли organization). Org-leader сохраняет управление командой, но комиссию больше не видит.
- `/manager/finance` для рядового менеджера — без блока комиссии (уже так, закрепляем тестом).
- Тест-инвариант: рендер org-finance и manager-finance (не-лидер) не содержит строк комиссии.

## §5. Мелкое единообразие (одним проходом)

- **КПИ-плитки кликабельны**: `StatCard` получает опциональный `href` (вся плитка — ссылка на соответствующий список); дашборды передают адреса.
- **Форматтеры** `fmtMoney`/`fmtDate`/`fmtDateTime` в `src/lib/format.ts`; sweep по местам с ручным форматированием (лента событий менеджера показывает «250000 ₽», даты пляшут между `01.01.25` / `01.01.2026, 22:41`).
- **Бренд**: «Промтехносфера» в логотипе (auth, шеллы), футере («Промтехносфера © 2026»), title вкладки.
- **«Сделки» → «Заказы»** во всех надписях партнёрского кабинета (меню, заголовки, «← Все сделки», пустые состояния, бейджи). URL не трогаем.
- **«← Назад»-ссылки**: единый мини-компонент `BackLink` (формат «← Все заказы» / «← Все отчёты»: «← Все + мн. число раздела»).
- **Пустые состояния**: везде общий `EmptyState` (иконка + текст + CTA, где действие существует); голые `<td>Ничего не нашли</td>` уходят; в пустом чате — подсказка, как начать переписку; в пустых «Финансах» менеджера — «Обратитесь к администратору, чтобы вам назначили организации».
- **Страница слушателя** (`/student` для орг-пользователя): рендер в родной оболочке пользователя (сейчас выпадает в чужой generic-shell с другой шапкой) + человеческий текст без «LMS» («Обучение проходит на отдельной учебной площадке. Нажмите кнопку — вход произойдёт автоматически, пароль не нужен»).
- **Кавычки**: имена организаций не оборачиваем в «» (имя уже содержит свои: «ООО «Завод Прима»» → ООО «Завод Прима»).
- **Демо-вход**: добавить кнопку «Студент» + seed-аккаунт `student@demo.local` (кнопка «Руководитель» — в спеке кабинета руководителя, вместе со своим seed-аккаунтом).

## Вне scope (намеренно)

- Миграция форм на `useFormAction` — идущий трек (Фазы 2–4 tier2-dedup), не дублируем.
- Кабинет руководителя — отдельная спека.
- Противоречивые даты в демо-данных (заказ «закрыт» раньше «создан») — артефакт сида, не UI.

## Тестовая стратегия

- **Unit**: словари enum (включая unknown-fallback); правило payment-бейджа (3 ветки + долг>0); guardrail-тесты сайдбаров (рендер = канон); `LogoutButton` (POST + redirect); `BackLink`/`StatCard href`.
- **Обновить**: components.admin-sidebar.test (русские названия, группы из канона), manager-sidebar тесты, тесты humanStage (мужской род).
- **Инвариант комиссии**: org-finance и manager-finance (не-лидер) без строк комиссии.
- **E2E visual**: обновить baselines (`npm run e2e:visual:update`) — меню и шапки меняются во всех кабинетах.
- **Ручной smoke**: вход за каждую роль → выход; `/` и `/forbidden` под каждой ролью.
