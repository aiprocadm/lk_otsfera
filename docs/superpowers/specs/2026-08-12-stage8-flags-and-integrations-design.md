# Этап 8 — управление флагами и интеграциями из интерфейса

**ТЗ:** [понятность интерфейса и закрытие функциональных пробелов](../../tz/2026-08-08-tz-usability-and-core-gaps.md), требования `У-65`…`У-70`.
**Дата:** 12.08.2026. **Статус:** ждёт подтверждения заказчика.

## 0. Коротко

Сейчас, чтобы включить функцию или канал уведомлений, нужно зайти на сервер и
поправить переменную окружения. Этап переносит переключатели в интерфейс.

**Но одну вещь так перенести нельзя, и это главный вопрос спеки** (§2.1):
часть флагов читается в «пограничном» слое Next (middleware), где базы данных
нет вообще. Ниже — что с этим делать; я предлагаю вариант, но решение за вами.

## 1. Что показала сверка кода (§16)

| Требование | Что в коде сейчас |

| `У-67` | Аудит правок настроек интеграций есть; для флагов действия нет |
| `У-68` | Подтверждения нет (нечего подтверждать — переключателей нет) |
| `У-69` | Ключи Max/WhatsApp/Mango вводятся на странице интеграций, а включение канала — только env. Ровно то, на что жалуется ТЗ |
| `У-70` | **Почти готово:** проба «Проверить подключение» пишет `SyncState` (`lastRunAt` / `lastSuccessAt` / `lastError`), страница уже показывает дату и текст ошибки. Не хватает явного третьего состояния «не настроено» и единого вида светофора |

**Ключевой факт:** `isFeatureEnabled` — **синхронная** функция, её читают
**75 файлов**, в том числе `src/middleware.ts`.

## 2. Решения, которые предлагаю

### 2.1. Главный вопрос: флаги, которые читает middleware

Middleware Next выполняется в edge-среде: Prisma там недоступна. Поэтому
route-флаги (те, что закрывают целые разделы: `/manager/*`, `/leader/analytics`,
`/organization/certificates` и т. д.) не могут читать значение из базы.

Это не догадка — в коде уже записано это же ограничение: телефония Mango
намеренно **не** переехала в настройки интеграций, «флаг читается в
edge-middleware, где БД недоступна — переключатель в БД не смог бы влиять на
route-гейт и создавал бы иллюзию управления».

Что важно понять про направление переключения:

- **выключить** флаг из базы можно и без middleware: у каждого раздела есть
  ещё два гейта — пункт меню и проверка на самой странице (правило «трёх
  точек», §5 CLAUDE.md). Раздел исчезнет из меню и перестанет открываться;
- **включить** — нельзя: middleware отдаст 404 раньше, чем страница успеет
  посмотреть в базу. Кнопка будет нажиматься, а раздел не появится.

Варианты:

| | Что делаем | Плюсы | Минусы |
|---|---|---|---|
| **А (предлагаю)** | В базе управляются **поведенческие** флаги (каналы, 2FA, журнал ПДн, генерация документов, чат, вопросы из кабинета). Route-флаги остаются за env и на экране показаны **только для чтения** с пояснением «раздел включается на сервере» | Честно: каждый переключатель на экране действительно работает. Ноль риска «мнимого управления» | Часть флагов по-прежнему требует SSH — то есть `У-65` закрыт не полностью |
| **Б** | Middleware спрашивает значения по сети у самого приложения (внутренний маршрут) и кэширует на 30 сек | Формально все флаги из UI | Сетевой запрос на КАЖДЫЙ запрос страницы, новая точка отказа, задержка. За надёжность плачу первым делом |
| **В** | Значения флагов кладутся в подписанную cookie при входе | Middleware читает без базы | Значение живёт до перелогина; у разных пользователей разное состояние системы — это уже не «флаг системы» |

**Почему А.** Требование `У-65` про то, чтобы «не ходить на сервер», а вариант
Б платит за это задержкой на каждом запросе и новой поломкой. Вариант В делает
состояние системы разным у разных людей — это хуже, чем честная надпись.

### 2.2. Как переносим (`У-65`, `У-66`, `У-67`)

Ничего нового изобретать не нужно — механизм настроек интеграций подходит
целиком:

- значения флагов хранятся строками в **`IntegrationSetting`** (ключи вида
  `feature.max_channel`) — отдельную таблицу `Setting` не заводим: две таблицы
  одного назначения разъедутся;
- `isFeatureEnabled` остаётся **синхронной** и читает снапшот, который уже
  умеет TTL, откат к env и «до первого прайма — как раньше». Порядок
  источников ровно по `У-66`: **база → env → умолчание**;
- на экране у каждого флага видно, **откуда** значение («задано в интерфейсе» /
  «переменная окружения» / «по умолчанию»);
- каждое переключение пишется в `AuditLog` новым действием
  `feature_flag.changed` с «из чего → во что» (`У-67`).

### 2.3. Подтверждение опасных переключений (`У-68`)

Диалог с текстом последствия для флагов, влияющих на доступ и деньги
(`role_constructor`, `pii_access_log`, `commission_pdf`, `commission_xlsx`).
Текст не общий, а конкретный: «журнал доступа к персональным данным
перестанет вестись — это нарушает требования по защите ПДн; включайте паузу
только на время инцидента».

### 2.4. Каналы и светофор (`У-69`, `У-70`)

- Включение канала переезжает на карточку канала — туда же, где вводятся
  ключи. Технически это те же поведенческие флаги из §2.2, просто показанные
  рядом с полями. Телефония Mango — route-флаг, поэтому у неё переключателя не
  будет (см. §2.1), и на карточке об этом сказано прямо.
- Светофор: три состояния — **работает** (последняя проба успешна, с датой) ·
  **не настроено** (нет обязательных ключей) · **ошибка** (текст последней).
  Данные для этого уже есть, нужен единый вид и состояние «не настроено».

### 2.5. Порядок: два PR

| PR | Что | Требования |
|---|---|---|
| **PR-1 «переключатели»** | Флаги в базе, приоритет источников, аудит, редактируемая матрица с подтверждением опасных | `У-65`…`У-68` |
| **PR-2 «интеграции»** | Включение каналов на карточке ключей + светофор трёх состояний | `У-69`, `У-70` |

## 3. Тесты

- приоритет источников: база перекрывает env, env перекрывает умолчание,
  удаление значения из базы возвращает env-поведение;
- синхронный читатель до первого прайма ведёт себя как раньше (env);
- переключение пишет аудит с прежним и новым значением; действие есть в
  словаре русских названий;
- опасный флаг без подтверждения не переключается;
- route-флаг из интерфейса не переключается вовсе (страж: иначе получим
  «мнимое управление»);
- светофор: три состояния и то, что «ошибка» показывает текст последней;
- права: не-админ не видит экран и получает отказ от действия.

## 4. Риски

| Риск | Что делаем |
|---|---|
| Флаг выключили, а он читается в 75 местах — часть могла закэшировать значение | Снапшот с TTL 30 сек уже есть; на экране пишем «изменения применяются в течение минуты» |
| Кто-то выключит журнал ПДн и забудет | Подтверждение с текстом последствия (`У-68`) + запись в аудит; журнал остаётся opt-out по умолчанию |
| Переключатель route-флага в UI создаст иллюзию управления | Такие флаги показываются только для чтения, с явной подписью (§2.1) |
| Две таблицы настроек разъедутся | Переиспользуем `IntegrationSetting`, новую таблицу не заводим |
