## 2. Модели (PR-1, PR-4)

```prisma
enum CatalogUnit { person piece service hour month }   // чел·шт·услуга·час·месяц

model CatalogItem {
  id          String   @id @default(cuid())
  companyId   String   // каталог у каждой компании свой
  name        String
  code        String   // артикул; @@unique([companyId, code])
  unit        CatalogUnit @default(person)
  price       Decimal  @db.Decimal(14, 2)
  vatRate     Decimal? @db.Decimal(5, 4)  // null = не облагается
  vatIncluded Boolean  @default(true)
  directionId String?  // связь с направлением обучения, необязательная
  description String?
  isActive    Boolean  @default(true)     // деактивация вместо удаления
  sortOrder   Int      @default(0)
  createdAt/updatedAt
  @@unique([companyId, code])
  @@index([companyId, isActive, sortOrder])
}

model OrderLine {
  id             String   @id @default(cuid())
  orderId        String   // FK Order, onDelete: Cascade
  catalogItemId  String?  // FK CatalogItem, onDelete: Restrict (элемент не удаляется физически)
  title          String   // снимок наименования
  quantity       Decimal  @db.Decimal(12, 3)
  unit           CatalogUnit
  unitPrice      Decimal  @db.Decimal(14, 2)
  discountPercent Decimal? @db.Decimal(5, 2)
  vatRate        Decimal? @db.Decimal(5, 4)
  vatIncluded    Boolean
  amount         Decimal  @db.Decimal(14, 2) // СНИМОК суммы строки (Р-13)
  sortOrder      Int      @default(0)
  createdAt/updatedAt
  @@index([orderId, sortOrder])
}
```

`Company` дополняется (`У-138`): `defaultVatRate Decimal(5,4)?` (null = «не
облагается, УСН»; допустимые значения 0 / 0.05 / 0.07 / 0.10 / 0.20 —
валидация в сервисе), `pricesIncludeVat Boolean @default(true)`, `logoKey` /
`signatureKey` / `stampKey String?` (ключи S3), `documentNumbering Json?`
(шаблон нумерации: `{ prefixes: {invoice?, act?, contract?, supplementary?},
resetYearly: boolean }`, Zod-схема в сервисе; применяет его генератор
этапа 6 — здесь только редактирование и хранение).

`Order` дополняется: `totalAmountIsManual Boolean @default(false)` —
плашка «сумма задана вручную» (`У-140`).

Расчёт суммы строки (единая чистая функция с юнит-тестами, служит и
этапу 6): `amount = round2(quantity × unitPrice × (1 − discount/100))`;
НДС: при `vatIncluded` — `vat = amount × rate/(1+rate)`, иначе `vat = amount
× rate`, итог «с НДС» соответственно. Суммирование — на `Prisma.Decimal`
(проектный канон: float даёт дрейф в копейках), наружу — строка/число один
раз на выходе DTO.

## 3. Экраны

### 3.1. «Каталог услуг и цены» — хаб, `catalogs.priceList` (PR-1, PR-2)

Реестр: `id: 'catalogs.priceList'`, `path: 'catalogs/price-list'`, группа
`catalogs`, право `settings.catalogs.manage`, `cabinets: ['admin','leader']`
(матрица `У-135` расширяется тем же PR). Скоуп как у реквизитов: админ — все
компании (селектор компании над таблицей), руководитель — своя
(sentinel `__none__` без компании).

Экран (общий презентационный, `Р-23`): `PageHeader` («Каталог услуг и цены» /
«Услуги и товары вашей компании с ценами — из них собираются строки заказов
и документов»), поиск по названию/артикулу, таблица (Название · Артикул ·
Ед. · Цена · НДС · Направление · Активен · Действия), диалог
добавления/правки (`Dialog`-примитив), деактивация с подтверждением
(использованный элемент не удаляется физически — всегда только `isActive =
false`), фильтр «показывать неактивные». Пустое состояние — `EmptyState` с
кнопкой «Добавить услугу» и кнопкой «Импорт из Excel». История изменений
цены — аудит (`catalog_item_updated` с `before/after`), просмотр — в
существующем разделе «Аудит»; на карточке позиции — счётчик «цена менялась
N раз» не делаем (не в ТЗ).

Кнопки «Шаблон Excel» · «Импорт» · «Экспорт» (PR-2): импорт в два шага по
эталону сотрудников (предпросмотр «будет создано / обновлено / ошибок» →
подтверждение; сопоставление по `code`; строки между шагами не
перечитываются), экспорт — синхронный роут на helpers `export/xlsx.ts`
(`safeText`, лимит 10 000 со сноской), шаблон — роут по образцу
`students/import-template` (те же колонки-константы, что у парсера).

### 3.2. Налоги и оформление компании (PR-3, `У-138`)

Расширяется существующий раздел **«Реквизиты исполнителя»**
(`catalogs.requisites`) — отдельная секция не заводится: налоги, логотип и
нумерация — это свойства того же исполнителя, а «один объект — одно место»
(§0.2). В карточку компании добавляются три блока:

- **Налоги**: селект «Ставка НДС по умолчанию» (0% · 5% · 7% · 10% · 20% ·
  «не облагается (УСН)») + чекбокс «цены включают НДС». Пишется
  `setCompanyRequisites`-соседним действием с той же границей leader-компании.
- **Оформление документов**: логотип, подпись, печать — три слота
  (PNG/SVG, до 1 МБ). Загрузка — файловый API-роут (§11; `useFetchSubmit`),
  magic-bytes (PNG есть; SVG — по сигнатуре `<svg`/`<?xml` + запрет
  `<script`/`onload=` в содержимом), путь S3
  `company/<id>/branding/<slot>-<uuid>.<ext>`, скан ClamAV новой целью
  `company_branding` (ветка процессора + integration-тест — страж
  `worker.processor-coverage` этого требует), предпросмотр `<img>` по
  presigned URL (скачивание — только `Content-Disposition: attachment`:
  SVG при прямой навигации исполняет скрипты, во `<img>` — нет). Пока файл
  не прошёл скан — плашка «проверяется антивирусом»; `infected` — слот
  очищается, событие аудита.
- **Нумерация документов**: префиксы по типам (счёт/акт/договор/ДС) +
  чекбокс «обнулять счётчик каждый год». Только хранение и валидация;
  применяет генератор этапа 6.

### 3.3. «Состав и стоимость» на карточке заказа (PR-4, `У-139`/`У-140`)

Общий презентационный блок `OrderLinesSection` во всех трёх кабинетах:
manager+leader — внутрь `ManagerOrderDetailView` (рядом с «Финансы»),
admin — на его страницу (у админа блока позиций сейчас нет вовсе — приводим
карточки к зеркалу в этой части). Данные собирает страница/лоадер, компонент
в базу не ходит (`components-no-db`).

- Таблица строк: № · Наименование · Кол-во · Ед. · Цена · Скидка · НДС ·
  Сумма; итоги «без НДС / НДС / с НДС».
- Добавление: выбор из каталога с поиском (цена и НДС предзаполняются из
  элемента и **правятся вручную** — снимок, `Р-13`) либо свободная строка.
- Кнопка **«Собрать строки из позиций»**: группирует `OrderItem` по
  направлению → строки «<направление> × N чел.»; цена — из элемента
  каталога, СВЯЗАННОГО с направлением (`directionId`); направления без
  связанного элемента попадают строками с ценой 0 и предупреждением —
  молча пропускать нельзя (§15).
- `Order.totalAmount`: **при наличии строк** пересчитывается из строк
  каждым изменением; ручная правка суммы (новая возможность, только staff)
  при наличии строк ставит `totalAmountIsManual` + плашка + аудит; следующее
  изменение строк спрашивает: «сумма задана вручную — пересчитать по
  строкам?». Для заказов **без строк** поведение прежнее (сумма-снимок не
  трогается).
- **Заказы из 1С** (`externalId != null`): строки и сумма — только чтение
  (плашка «заказ ведётся в 1С»); `totalAmount` остаётся собственностью
  синка (`ownedBy1C`).
- Инвариант-тест `invariants.price-snapshot` **переписывается** (это велит
  само ТЗ, `Р-13`): снимок живёт у `OrderLine.amount` (правка каталога не
  меняет существующие строки — прямая проба), сумма заказа выводится из
  строк; прежняя формулировка сохраняется для заказов без строк и для 1С.

## 4. Миграции — два шага, порядок жёсткий

1. **PR-1/PR-3/PR-4 — аддитивные**: `CatalogItem`, поля `Company`,
   `OrderLine` + `Order.totalAmountIsManual`. Генерация через
   `prisma migrate diff` (офлайн), как в этапе 4.
2. **PR-5 — миграция данных `У-139` отдельным PR (§5 ТЗ)**: удаление
   `OrderItem.amount`. Сначала dry-run скрипт
   `npm run report:order-item-amounts` (счётчик не-null значений, вывод
   «переносить нечего/есть N строк»); миграция начинается с
   `DO $$ ... IF EXISTS (SELECT 1 FROM "OrderItem" WHERE amount IS NOT NULL)
   THEN RAISE EXCEPTION ...` — падает внятным текстом, если хоть одно
   значение не null. Код перестаёт читать колонку в PR-4 (ветка
   попозиционной печати в `generate.ts:193–210` умирает — печать из строк
   придёт этапом 6, `У-141`), поэтому PR-5 идёт строго после PR-4.

## 6. Тестовая стратегия

- Юнит: расчёт строки (`amount`/НДС обе стороны `vatIncluded`, скидка,
  округление ROUND_HALF_UP), Zod нумерации, SVG-фильтр.
- Сервисы (mock-prisma): CRUD каталога (скоуп admin/leader, sentinel,
  деактивация вместо удаления, `duplicate_code`), импорт (создано/обновлено/
  ошибки, сопоставление по `code`), строки заказа (снимок при добавлении,
  пересчёт totalAmount, ручная сумма + флаг, 1С → `forbidden`, «Собрать из
  позиций» с направлением без элемента каталога).
- Integration: переписанный `invariants.price-snapshot`; скан
  `company_branding` (страж worker.processor-coverage).
- Стражи, правимые теми же PR: `security.settings-matrix` (LEADER_SECTIONS),
  `lib.auth.settings-access` (список leader), `pages.subtitles` (PageHeader
  на новых экранах), `ui.empty-states` (EmptyState с кнопкой). Каждый новый
  страж/правка — с мутацией (§16).
- Глоссарий: термины «Каталог услуг и цены», «Строка заказа», «Позиция
  (слушатель × направление)» — в `docs/glossary.md` тем же PR, где
  появляются на экране (`У-76`).
