# Этап 7 программы ПМ — сообщения, почта, уведомления (спека)

**ТЗ:** [2026-10-13-tz-pm-review-student-manager.md](../../tz/2026-10-13-tz-pm-review-student-manager.md), §4 блок 7 (`У-313`…`У-318`).
**Решения:** `Р-ПМ-3` (дефект сначала воспроизвести), `Р-ПМ-5` (схема только аддитивно), `Р-ПМ-7` (стоп снят, решения принимает исполнитель), `В-ПМ-2` — умолчание (1). Разделы «Входящие письма» и «Мессенджеры» не объединяются ([NOT_DOING.md](../../NOT_DOING.md)).

## 1. Что есть сейчас

- **«Сообщения»** сотрудника (`/manager/messages`, `/leader/messages`) — один экран из трёх блоков друг под другом: «Комментарии к заказам», «Чат» (переписка с клиентами по заказам, флаг `chat`) и «Чат команды» (флаг `staff_chat`). До нижних блоков надо прокручивать первый целиком. В меню — один пункт, подпунктов меню не умеет.
- **Комментарии к заказам** собраны в блоки по заказу; блок нельзя свернуть.
- **Чат команды** уже только для сотрудников (`isStaff` в сервисе и в API). Личные сообщения сервер разрешает любому активному сотруднику своей компании и администраторам — воспроизведено на стенде 16.10.2026: `/api/staff-chat/colleagues` у `manager@demo.local` отдаёт администратора, руководителя и менеджера. Но в списке «+ Новое сообщение» только имена, без ролей и без поиска, — по ним не понять, кто есть кто. Своих чатов (кроме «# Общий» и личных) создать нельзя: у беседы два вида — `general` и `dm`.
- **«Входящие письма»** хранят тему (`InboundMessage.subject`), но копию (CC) не хранят и не показывают; ответ уходит без копии и без подписи.
- **Настройки уведомлений** — одна длинная таблица из 40 типов без групп.
- **«Входящие в работу»** собирают четыре источника: обращения из кабинета, заявки на обучение, сообщения каналов и звонки; фильтра по каналу и пометки «важное» нет.

## 2. Решения этапа

| № | Решение | Причина |
|---|---|---|
| `Р-7-1` | **«Сообщения» — пункт меню с тремя подпунктами**: «Комментарии по заказам» (`/…/messages`, по умолчанию), «Чаты с клиентами» (`/…/messages/chats`, флаг `chat`), «Чаты команды» (`/…/messages/team`, флаг `staff_chat`). Каждый подпункт — своя страница, свежее сверху; подпункт без флага не показывается. Меню получает поддержку подпунктов (`children` у пункта); у менеджера и руководителя — одинаково (правило зеркала) | `У-313` |
| `Р-7-2` | **Блок комментариев заказа сворачивается** заголовком (номер и название заказа, число сообщений); по умолчанию раскрыт | `У-314` |
| `Р-7-3` | **Свои чаты команды**: «+ Новый чат» — название и участники из сотрудников своей компании; новый вид беседы `group` и поле `title` (аддитивно). Видят чат только участники; администратор — по Model A. В «+ Новое сообщение» — роль рядом с именем и поиск по имени | `У-315` |
| `Р-7-4` | **Письмо выглядит как письмо**: в списке и в письме — тема крупно, отправитель, «Копия» (новое поле `InboundMessage.ccRecipients`, разбирается при приёме почты); в ответе — поле «Копия» и **автоматическая подпись** из профиля (имя, компания, почта, телефон), её видно в форме до отправки | `У-316` |
| `Р-7-5` | **Уведомления по группам**: «Системные», «Коммуникация», «Задачи», «Заказы», «Заявки на обучение» — у каждого типа реестра своя группа (страж полноты); группа — раскрывающийся список своих уведомлений | `У-317` |
| `Р-7-6` | **«Входящие обращения»** вместо «Входящих в работу»: только внешние каналы — сообщения мессенджеров и почты и звонки, фильтр по каналу, пометка «Важное» (поля `importantAt`/`importantById` у сообщения и звонка, аддитивно) и отбор «Только важные». Обращения из кабинета и заявки на обучение из этой очереди уходят — у них свои разделы. **Раздел «Обращения» остаётся**: в нём то, что клиент написал сам в кабинете, и убрать его значит потерять эти записи из вида. Пометка «важное» заменяет прежний обходной путь «превратить сообщение в обращение, чтобы не потерять», а не сам раздел | `У-318`, `В-ПМ-2` (1) |

## 4. Проверки

- Меню: подпункты у менеджера и руководителя одинаковые (страж зеркала), подпункт без флага скрыт, подсветка активного подпункта.
- Чат команды: заказчик и партнёр получают отказ от каждого API; участник чужого группового чата его не видит; мутация «группа без проверки участия» обязана ронять тест.
- Письма: CC разбирается из заголовков; подпись собирается из профиля и попадает в отправку; ответ с копией уходит всем адресатам.
- Уведомления: тип без группы роняет страж полноты.
- Входящие: фильтр по каналу и «Только важные» сужают выборку на сервере; пометка пишется в журнал; чужая компания пометить не может.
