# Этап 6 программы ПМ — заказы, лиды, организации, контакты (спека)

**ТЗ:** [2026-10-13-tz-pm-review-student-manager.md](../../tz/2026-10-13-tz-pm-review-student-manager.md), §4 блок 6 (`У-303`…`У-312`).
**Решения:** `Р-ПМ-5` (схема только аддитивно), `Р-ПМ-7` (стоп снят), `Р-Б-8` (таблицы `Comment` и `OrganizationNote` не трогаем), `В-ПМ-1` — умолчание (а), `В-ПМ-3` — умолчание (а). Порядковое ограничение ТЗ: `У-304` до `У-303`.

## 1. Что есть сейчас

- **Статусы заказа** — справочник `OrderStatusDefinition` (семь системных строк: «Черновик заявки», «Принято в работу», «Оплата поступила», «Документы выданы», «Бухгалтерия подписана», «Заявка закрыта», «Отменена»). На стенде порядок сбит: «Документы выданы» вторым, «Принято в работу» четвёртым. Раздел настроек называется «Статусы заявок» — а «заявка» по словарю это заявка на обучение.
- **«Бухгалтерия подписана»** — и этап воронки, и отметка `accountingSignedAt` в разделе «Бухгалтерия» карточки. Закрыть заказ без отметки уже нельзя (условие закрытия, панель статуса объясняет отказ).
- **Автоперевод по фактам** (`applyStatusAnchor`) в рабочем коде не вызывается.
- **Создать заказ** можно только из лида (`promoteLead`), из КП и из сделки.

## 2. Решения этапа

| № | Решение | Причина |
|---|---|---|
| `Р-6-1` | **Воронка заказа по умолчанию — четыре этапа в порядке работы**: «Черновик заявки» → «Принято в работу» → «Оплата поступила» → «Заказ закрыт»; «Отменена» — вне порядка. Миграцией данных системные строки получают этот порядок; «Заявка закрыта» переименовывается в «Заказ закрыт», если название не меняли | `У-304` |
| `Р-6-2` | **«Документы выданы» и «Бухгалтерия подписана» — факты, а не этапы**: строки остаются (якоря и история нужны), но выключены (`isActive=false`). Заказы, стоявшие на них, переходят на «Оплата поступила» (ближайший этап перед закрытием) с записью в истории статусов «Этап снят с воронки» | `У-304`, `У-305` |
| `Р-6-3` | **Подсказка менеджеру** в панели статуса: набор и порядок статусов настраивают руководитель и администратор — «Настройки → Справочники → Статусы заказов» (раздел переименован) | `У-304` |
| `Р-6-4` | **Раздел «Бухгалтерия» карточки** прямо говорит: «Без этой отметки заказ нельзя закрыть»; отказ закрытия — уже с объяснением | `У-305` |
| `Р-6-5` | **«Создать заказ»** рядом с выгрузкой: организация (из своих), название, вид работ; заказ сразу в «Черновике», ответственный — создавший менеджер; после создания — переход в карточку | `У-306` |
| `Р-6-6` | **Канбан заказов** — переключатель «Список / Канбан»; столбцы — активные этапы и «Отменена»; перетаскивание зовёт тот же `transitionOrderStatus` (те же проверки и объяснения отказа) | `У-303` |
| `Р-6-7` | **Статус лида из списка** — бейдж статуса открывает список статусов; смена — той же функцией, что в карточке лида | `У-307` |
| `Р-6-8` | **Менеджер создаёт организацию** — «Организации» → «Создать организацию»; новая сразу закреплена за ним (`OrganizationManager`) | `У-308` |
| `Р-6-9` | **Организация в форме контакта** — поиск по названию или ИНН среди своих и «Создать новую» прямо из формы | `У-309` |
| `Р-6-10` | **Заметки и переписка в заказе** — разные блоки с разными подписями и цветом; у сообщения клиента — «Создать заметку из этого сообщения» (копия в `OrganizationNote` с комментарием менеджера); таблицы не меняются | `У-310`, `Р-Б-8` |
| `Р-6-11` | **Описания «Лидов», «Сделок» и «Заказов»** — по одной строке, объясняющей разницу, на экранах и в справке | `У-311`, `В-ПМ-1` (а) |
| `Р-6-12` | **Воронка внутри «Лидов»** — переключатель «Список / Воронка»; пункт меню «Воронка продаж» убран, старый адрес отвечает «раздел переехал» со ссылкой | `У-312`, `В-ПМ-3` (а) |
