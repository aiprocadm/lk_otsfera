# Сопровождение, вопрос `В-1` → решение `Р-25`: «`log.warn` вместо тишины» — микро-спека

[MAINTENANCE.md](../../tz/MAINTENANCE.md) (находка `С-8` прогона №1, вопрос
`В-1` в [STATUS.md](../../tz/STATUS.md)) · **Статус:** решение принято
исполнителем по поручению заказчика («прими решение самостоятельно наиболее
эффективное»), реализовано этим PR.

## 1. Что было

Одиннадцать мест в `src/**` гасили отказ обработчиком `.catch(() => {})` или
`.catch(() => undefined)`. Восемь из них — **аудит и служебные записи**:
`recordAudit` при входе, 2FA (`2fa_code_sent`, `2fa_failed`, `2fa_verified`,
`2fa_backup_used`, `2fa_backup_regenerated`), «выйти на всех устройствах»
(`sessions_revoked`); отметка «последний вход» (`recordLastLogin`); журнал
синхронизации Mango (`writeSyncLog` в `mango-backfill`); удаление осиротевшего
файла из хранилища в приложениях к обращениям (два места). Если база или
хранилище отказывали, запись пропадала **молча** — ни строки в логе, ни
сигнала; человек узнал бы об этом только по пустому журналу аудита.

Три оставшихся места — не дефект: `Sentry.flush(2000)` перед
`process.exit(1)` в воркере (два раза; `log.error` уже записан, процесс
завершается) и `discardTwoFactorChallenge` (удаление уже истёкшего челленджа —
отказ ожидаемый).

Пустых блоков `catch {}` без комментария в коде нет: все тринадцать блоков
`catch { /* причина */ }` (клиентские хуки, `instrumentation.ts`, дашборд
администратора) содержат записанное объяснение — это осознанные решения.

## 2. Решение (`Р-25`)

Вариант (а) из `В-1`: **отказ best-effort операции не роняет действие, но
пишется в лог уровнем `warn`**. Варианты «оставить как есть» и «поднимать
ошибку» отклонены: первый оставляет пропажу аудита невидимой, второй ломает
вход из-за побочной записи (человек уже вошёл, код уже отправлен).

1. Хелпер `bestEffort(label)` в `src/lib/logging/bestEffort.ts`, экспорт через
   барель `@/lib/logging`: возвращает `(err) => log.warn(label, err)`.
   Промис после `.catch(bestEffort(...))` разрешается `undefined` — поведение
   вызывающих не меняется.
2. Восемь мест переведены на хелпер; метка — `[модуль] что failed (действие)`,
   как у уже существующих образцов (`[dlq/retry-all] audit failed`,
   `[worker] calculate-monthly-commissions writeSyncLog failed`).
3. Страж `src/__tests__/errors.no-silent-catch.guardrail.test.ts`: обходит
   `src/**` (без тестов и e2e), ищет `.catch(() => {})`,
   `.catch(() => undefined)`, `.catch(function () {})` (по коду без
   комментариев) и пустые `catch {}` без комментария внутри (по сырому тексту).
   Allow-list с точным числом вхождений и причиной: `src/worker/index.ts` ×2,
   `src/lib/services/auth/twoFactor.ts` ×1 — пропавшее или лишнее вхождение там
   тоже ловится.

## 3. Границы (§9.4 ТЗ)

Экраны, сущности, миграции, зависимости не трогаются. Тексты для человека не
меняются. Уровень `warn`, а не `error`: Sentry-алерт на побочную запись не
нужен, но строка в логе должна быть. `console.warn` в dev/test и pino-`warn`
в проде — через существующий логгер, без нового транспорта.
