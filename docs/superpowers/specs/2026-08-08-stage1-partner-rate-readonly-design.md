## 1. Зачем

Партнёр-администратор сейчас **сам себе назначает ставку комиссии**. На странице
`/partner/portfolio/[orgId]/settings` стоит форма, она шлёт `PUT` на
`/api/partner/portfolio/[orgId]/rate`, роут пропускает партнёра и пишет
`Organization.partnerCommissionRate`. В историю
`OrganizationCommissionRateChange` автором изменения записывается тот же партнёр.

Простыми словами: продавец сам выставляет себе процент вознаграждения, а учебный
центр узнаёт об этом постфактум. Это дыра в деньгах, поэтому этап идёт первым
(§5 ТЗ). Работа — чистое **вычитание**: экран для администратора уже есть
(`AdminRateOverrideForm` на `/admin/organizations/[id]`), новый писать не нужно.

## 3. Разведка по коду (факт на `main` `0cad2e84`, проверено командами)

1. **Роут** [`src/app/api/partner/portfolio/[orgId]/rate/route.ts`](../../../src/app/api/partner/portfolio/[orgId]/rate/route.ts):
   `getSession` → `requirePartnerAdmin` (из `@/lib/auth/guard`) → `canPartnerAccessOrg`
   → `setOrgCommissionRate` / `clearOrgCommissionRate`. Автор изменения —
   `session.sub`, то есть сам партнёр.
2. **Этот роут никто, кроме партнёрской формы, не вызывает.** Поиск по `src/`
   даёт только `rate-override-form.tsx` и два тестовых файла. Администратор
   меняет ставку **другим путём**: server action `setOrgRateOverrideFormAction`
   → `services/admin/orgRateOverride.ts` → тот же нижний сервис
   `rateOverride.ts`. То есть после закрытия роута админский путь не пострадает.
3. **Форма** `components/partner/rate-override-form.tsx` подключена **только** на
   `/partner/portfolio/[orgId]/settings` и является **единственным содержимым**
   этой страницы. Убрать её «просто так» — оставить пустой экран, а это дефект
   приёмки по §15 CLAUDE.md.
4. **Ставка уже показывается на чтение.** `OrgCardHeader` рисует плашку
   «Индивидуальная ставка комиссии: X%» + примечание. Но: показывается
   **только когда индивидуальная ставка задана**, и **нет пометки**
   «назначает учебный центр». То есть `У-3` выполнен наполовину.
5. **Вкладка «Настройки» помечена `adminOnly: true`** (`org-tabs.tsx`), значит
   обычный партнёр-менеджер её вообще не видит. Поэтому read-only строку по
   `У-3` нельзя класть на эту вкладку — часть партнёров ставку не увидит.
6. **Готовое к переиспользованию:** `services/commission/rateResolve.ts`
   (`resolveOrgRateAt` / `resolveRateAt`) уже умеет считать действующую ставку
   по правилу «индивидуальная организации → иначе историческая ставка партнёра →
   иначе `Partner.commissionRate`». Своей формулы не пишем.
7. **Грабля именования:** в репозитории **два разных** `requirePartnerAdmin` —
   в `@/lib/auth/guard` (возвращает `GuardResult`, для API) и в
   `@/lib/auth/requireRole` (бросает redirect, для страниц). Роут использует
   первый, страница — второй. При правке легко перепутать импорт.

## 4. Решения

### 4.1. `У-1` — форму удаляем целиком

- удалить файл `src/components/partner/rate-override-form.tsx`;
- удалить его тест `src/__tests__/components.partner-rate-override-form.test.tsx`;
- убрать импорт и рендер из `src/app/partner/portfolio/[orgId]/settings/page.tsx`.

Компонент именно **удаляется**, а не прячется за флагом: `Р-4` говорит «опции
быть не должно вообще». Плюс гейт `knip` в CI и так завалится на неиспользуемом
экспорте (так уже было в PR #326).

### 4.2. `У-2` — роут не удаляем, а закрываем для партнёра

Меняем гард: `requirePartnerAdmin` → `requireAdmin` (уже есть в
`@/lib/auth/guard`). Любой пользователь с ролью `partner` — независимо от
`partnerRole` — получает `403`.

**Почему не удалить роут целиком** (ТЗ разрешает оба варианта):

- `У-4` требует, чтобы попытка партнёра давала именно **`403`**. У удалённого
  роута Next вернёт `404` — букву требования это уже не выполняет, и страж
  пришлось бы писать «на отсутствие файла», что ничего не доказывает о
  поведении;
- `У-2` прямо оставляет опцию «роут остаётся только для внутренних ролей».

Тело роута (валидация, вызов сервиса) не трогаем — меняется одна строка гарда.

### 4.3. `У-3` — действующая ставка строкой, только на чтение

Правим плашку в `components/partner/org-card-header.tsx`:

- показывать **всегда**, а не только при заданной индивидуальной ставке;
- текст: `Ставка комиссии: 8.00% · назначает учебный центр`;
- если ставка индивидуальная — дополнительно слово «индивидуальная» и
  примечание (`partnerCommissionRateNote`), как сейчас;
- источник числа — `resolveOrgRateAt` из `services/commission/rateResolve.ts`,
  чтобы на экране была та же ставка, по которой реально считаются деньги.

`getOrgCard` расширяется одним полем `effectiveCommissionRate: string` (базовая
ставка партнёра нужна для случая «индивидуальной нет»). Никаких новых запросов
в цикле — `Partner.commissionRate` берётся тем же `findFirst`.

Плашка живёт в шапке карточки, значит видна **всем** партнёрским ролям и на всех
вкладках портфеля — это и есть «строка в карточке организации» из `У-3`.

### 4.4. Страница «Настройки» не остаётся пустой (§15 CLAUDE.md)

После удаления формы на вкладке не остаётся ничего. По правилу трёх вопросов
экран получает:

- **где я** — заголовок «Настройки организации» (крошки и подсветка уже есть);
- **что здесь делают** — подзаголовок в одну строку: «Условия работы по этой
  организации. Ставку комиссии назначает учебный центр.»;
- **что делать дальше** — блок пустого состояния: «Здесь пока нечего менять» +
  ссылка «Написать менеджеру» на существующий экран комментариев
  (`/partner/portfolio/[orgId]?tab=comments`).

Вкладку **не скрываем**: этап 4 (`У-60`…`У-64`) переносит сюда «Доступ к
организации» и реквизиты. Скрыть сейчас и вернуть через этап — лишняя работа и
два разъезда в тестах.

### 4.5. `У-4` — тест-страж

`src/__tests__/api.partner.portfolio.rate.test.ts` переписывается: вместо
проверок «партнёр-админ успешно меняет ставку» — страж по букве `У-4`.

Проверяются **оба факта разом**:

1. `PUT` от сессии с ролью `partner` (и `partnerRole: 'admin'`, и обычной) →
   статус `403`;
2. `prisma.organizationCommissionRateChange.create` **не вызван** ни разу, и
   `organization.update` тоже.

Второй пункт обязателен: один статус ответа не доказывает, что запись не
появилась (прямое указание шапки STATUS.md).

## 8. Решения, требующие «ок» заказчика

1. **Роут `PUT …/rate` закрываем (403), а не удаляем.** ТЗ разрешает оба
   варианта; выбран первый — иначе `У-4` не выполняется буквально (у удалённого
   роута ответ `404`, а не `403`). Согласны?
2. **Показывать ставку всегда, даже когда индивидуальной нет** (тогда
   показывается базовая ставка партнёра). Альтернатива — показывать плашку
   только при индивидуальной ставке, как сейчас; но тогда партнёр без
   индивидуальной ставки не видит **никакой** — а `У-3` говорит «видит
   действующую». Согласны?
3. **Вкладку «Настройки» оставляем** (с подзаголовком и пустым состоянием) —
   этап 4 положит туда реквизиты и доступ к организации. Альтернатива — скрыть
   вкладку до этапа 4. Согласны?
