## 3. Дизайн

### ФТ-5.1 — блок «Готовность к передаче» на деталке заказа (staff)

Расширяем `evaluateOrderCompletion` до **попозиционной** картины:

- `serviceType='training'` — по каждой `OrderItem`: обучение завершено ·
  удостоверение создано · скан удостоверения загружен (`Certificate.documentId`).
- `serviceType='document_development'` — загружены итоговые документы
  (`Document.direction='outgoing'`, `scanStatus='clean'`).
- Существующие условия (`accounting_signed`, `documents_uploaded`) остаются:
  блок **расширяет**, а не заменяет «список несоблюдённых условий завершения».

Функция остаётся чистой и юнит-тестируемой (без БД) — как сейчас.

### ФТ-5.2 — кнопка «Передать результат клиенту»

- Активна **только** при полной готовности (иначе — disabled + список
  недостающего, как у генерации документов этапа 8).
- Ставит `Order.resultDeliveredAt` (аддитивная миграция, nullable).
- Идемпотентность: повторное нажатие не перезаписывает дату и не шлёт второе
  уведомление (проверка `resultDeliveredAt === null` внутри транзакции).
- Уведомление `order_result_delivered` организации и — если заказ партнёрский —
  партнёру; ссылка на реестр удостоверений (обучение) или документы.
- Аудит: `order_result_delivered`, entity `order`.

### ФТ-5.3 — массовая загрузка сканов удостоверений

- На заказе: мультизагрузка файлов с сопоставлением «файл → позиция»
  (выбор слушателя вручную).
- Автоподстановка по совпадению ФИО в имени файла — **подсказка**, требующая
  ручного подтверждения (ТЗ: «с обязательным ручным подтверждением»).
- Каждый файл — обычный `Document` со сканом ClamAV и записью в аудит, как при
  одиночной загрузке (переиспользуем `persistUploadedDocument`).

### ФТ-5.4 — клиентский степпер

`humanStage` получает финальную точку **«Результат передан»** с датой
`resultDeliveredAt`. Для клиента это ответ на вопрос «моё готово?» без звонка
менеджеру.

## 5. Тестовая стратегия

- `evaluateOrderCompletion`: попозиционные ветки, оба типа услуги, пустые позиции.
- Передача: недоступна при неполной готовности; идемпотентность (второе нажатие
  — no-op); уведомление уходит организации и партнёру; аудит записан.
- Клиентский степпер: точка появляется только после передачи.
- Массовая загрузка: сопоставление, автоподсказка требует подтверждения,
  заражённый файл не привязывается.
- Integration на живом Postgres: полный путь «все условия выполнены → передача →
  клиент видит "Результат передан"».
- Порог покрытия 100% на изменённые слои.
