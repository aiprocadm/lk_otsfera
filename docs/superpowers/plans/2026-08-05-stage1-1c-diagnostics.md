# Этап 1 «Диагностика импорта 1С» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans.

**Goal:** сделать видимой причину, по которой загрузка файла из 1С не даёт
результата: скрипт-инспектор файла, реальные записи в журнал вместо пустого
`catch {}` и блок «Что увидела система в файле» в отчёте импорта.

**Спека:** [2026-08-05-stage1-1c-diagnostics-design.md](../specs/2026-08-05-stage1-1c-diagnostics-design.md) — подтверждена заказчиком 05.08.2026.
**ТЗ:** [починка импорта 1С](../../tz/2026-08-04-tz-fix-1c-import.md), §2 «Этап 0», Т-1…Т-3.

## Global Constraints

- Объём — **строго Т-1…Т-3**. Карту колонок не трогаем (этап 3), `catch` в формах
  и лимит размера — этап 2, организации — этап 5.
- Схема БД, права и контракты API не меняются; миграций нет.
- Порог покрытия 100% на `src/**` — новый код приходит со своими тестами.
- Русский в UI и в выводе скрипта; коды ошибок остаются английскими.
- Одна ветка `stage1-1c-diagnostics`, один PR с `base: main` (уже открыт как
  черновик #310 со спекой).

### Задача 1: тип и сборщик диагностики

**Файлы:**
- Создать: `src/lib/services/import/diagnostics.ts`
- Тест: `src/__tests__/import.diagnostics.unit.test.ts`

**Produces:**
```ts
export type ImportDiagnostics = {
  sheetsFound: string[];
  sheetsExpected: string[];
  unmatchedHeaders: Record<string, string[]>;
};
/** Заголовки листа, которых нет в карте колонок. Пустые ячейки шапки игнорируются. */
export function unmatchedHeadersOf(headers: string[], cols: Record<string, string>): string[];
```

Лист-модуль без зависимостей: его тип импортирует и клиентский компонент
(`import type`), поэтому тянуть сюда exceljs нельзя.

- [ ] **Шаг 1:** тест: заголовок из карты → не в списке; чужой заголовок → в списке;
      пустые строки и дубли отбрасываются; порядок сохраняется.
- [ ] **Шаг 2:** прогнать — падает.
- [ ] **Шаг 3:** реализовать.
- [ ] **Шаг 4:** зелёный.

### Задача 2: `parseWorkbook` возвращает диагностику (Т-3, часть 1)

**Файлы:**
- Изменить: `src/lib/services/import/parse-workbook.ts`
- Тест: `src/__tests__/import.parse-workbook.test.ts` (дополнить)

`readSheet` начинает отдавать `{ rows, unmatchedHeaders }`; `parseWorkbook`
собирает из этого `diagnostics`:

```ts
diagnostics: {
  sheetsFound: wb.worksheets.map((ws) => ws.name),
  sheetsExpected: Object.values(SHEET_NAMES),
  // ключ — ФАКТИЧЕСКОЕ имя листа; ненайденного листа в ключах нет вовсе
  unmatchedHeaders: { …только для найденных листов },
}
```

- [ ] **Шаг 1:** тесты: книга со всеми тремя листами → `unmatchedHeaders` пуст,
      `sheetsFound` содержит три имени; лишняя колонка → попала в
      `unmatchedHeaders` под именем своего листа; книга с чужими именами листов →
      имена видны в `sheetsFound`, ключей в `unmatchedHeaders` нет, строки пусты.
- [ ] **Шаг 2:** прогнать — падает.
- [ ] **Шаг 3:** реализовать.
- [ ] **Шаг 4:** зелёные, включая существующие тесты парсера.

### Задача 4: отчёт импорта и журнал (Т-2 + Т-3, часть 3)

**Файлы:**
- Изменить: `src/lib/services/import/index.ts`

```ts
export type ImportReport = {
  orders: BatchSummary;
  payments: BatchSummary;

type Failure = { ok: false; error: Err; diagnostics?: ImportDiagnostics };

} catch (e) {
```

### Задача 6: скрипт-инспектор (Т-1)

**Файлы:**
- Создать: `scripts/inspect-1c-xlsx.ts`
- Изменить: `package.json` (ярлык `inspect:1c`)

Печатает: имя и размер файла, формат по сигнатуре (`PK` → xlsx, `D0 CF 11 E0` →
xls с подсказкой «пересохраните из 1С в xlsx»), список листов, по каждому
найденному листу — распознанные заголовки (`заголовок → поле`), нераспознанные,
недостающие колонки карты и первые 3 строки. В конце — какие листы ожидались и
каких не нашлось.

Без БД и сети. Код возврата всегда 0 (инструмент, а не проверка). Карта колонок
импортируется из боевой `column-map.ts` — копии не заводим.

- [ ] **Шаг 1:** реализовать скрипт.
- [ ] **Шаг 2:** ручная проверка: собрать во временной папке xlsx с «правильным»
      и с «кривым» листом, прогнать скрипт на обоих, убедиться, что вывод
      различает случаи. Временные файлы не коммитить.
- [ ] **Шаг 3:** добавить ярлык в `package.json`, проверить `npm run inspect:1c`.
