## Отличия от плана

Плана держались дословно; единственное уточнение — по ответу заказчика **не**
расширяли `getOrgCard` полем `effectiveCommissionRate`: показывается только
индивидуальная ставка, как было.

## Решения заказчика (зафиксированы, влияют на будущие сверки)

1. Роут **закрыт** (`403`), а не удалён — `У-4` требует именно `403`.
2. Ставка показывается **только особая**. Следствие: партнёр без индивидуальной
   ставки не видит на экране **никакой** — базовая ставка партнёра ему не
   показывается. Оговорка продублирована в [AUDIT.md](../../tz/AUDIT.md), блок A,
   чтобы следующая сверка не сочла это расхождением.
3. Вкладка «Настройки» **оставлена** — этап 4 (`У-60`…`У-64`) положит туда
   реквизиты и «Доступ к организации».

## Что узнали по ходу (пригодится соседним этапам)

- **API-роут `PUT …/rate` вызывала только партнёрская форма.** Администратор
  меняет ставку через server action → `applyOrgRateOverride`
  (`services/admin/orgRateOverride.ts`), который сам резолвит `partnerId` по
  организации. Эту логику не писать заново.
- **`canPartnerAccessOrg` возвращает `false` для любой не-партнёрской сессии** —
  оставленный в админском роуте предикат сделал бы роут мёртвым.
- **Два разных `requirePartnerAdmin`:** `@/lib/auth/guard` (`GuardResult`, для
  API) и `@/lib/auth/requireRole` (redirect, для страниц).
- **Вкладка «Настройки» портфеля помечена `adminOnly`** — обычный партнёрский
  пользователь её не видит, поэтому read-only данные для всех партнёров кладутся
  в `OrgCardHeader`, а не на эту вкладку.

## Грабли прогонов

1. **Тест пустого состояния падал не по делу:** кнопка «Написать менеджеру»
   ведёт на тот же адрес, что вкладка «Комментарии», и `querySelector` брал
   вкладку. Лечение — искать среди всех ссылок по тексту.
2. **Integration-страж падал на FK `AuditLog_userId_fkey`:** сервис ставки пишет
   аудит в той же транзакции, поэтому админа нужно заводить настоящим `User`, а
   не выдуманным `sub`.
3. **В worktree нет своего `node_modules`,** а npm-скрипты зашивают
   `./node_modules/...` — гейты гонялись через `npx --no-install`, коммит и пуш с
   `--no-verify`. Симлинк на общий `node_modules` ставить нельзя: vitest уже
   создаёт там свой `.vite`, и ссылка ложится внутрь него.
4. **Integration-тесты не читают `.env` сами** — `NODE_OPTIONS="-r dotenv/config"`.
5. **`knip` / `dependency-cruiser` / `jscpd` физически отсутствуют** в
   `node_modules` — их гоняет только CI; осиротевшие экспорты проверялись грепом
   вручную (`requirePartnerAdmin` остался у роутов команды и финансов).
