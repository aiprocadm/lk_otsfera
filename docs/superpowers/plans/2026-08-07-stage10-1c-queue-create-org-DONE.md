## Решения, закреплённые в коде

1. **Права — `mayImportOneC`** (§8.1 спеки): обычный менеджер — `forbidden`;
   руководитель — только строки своей компании (чужая = `not_found`).
2. **`org_exists` вместо молчаливой привязки** (§8.2): организация с таким ИНН
   уже есть → оператор осознанно жмёт штатную «Привязать»; строка очереди
   остаётся `needs_review`.
3. **Создание и привязка — два шага** (§8.3): упавшая привязка возвращает
   `bind_failed` с id созданной организации, не откатывая её.
4. **`externalId` новой организации пуст** (§8.4): ключ `1c-inn:<ИНН>` допишет
   первый файловый импорт (существующий backfill этапа 5) — закреплено
   integration-тестом.
5. Компания — правила Т-41: руководитель из скоупа (параметр игнорируется),
   admin — селект в диалоге с prefill компанией батча; `listQueue` для этого
   отдаёт `batch.companyId`.
6. Аудит — существующее действие `organization_created_manual` c
   `after.source: 'payment_queue'` (реестр не разросся).

## Грабли этого этапа

- Экстрактор номера документа выписки требует форму `\d{2,}-\d{3,}` — номер
  `...-01` (2 цифры после дефиса) молча не распознаётся, строка не попадает в
  очередь.
- Мок `@/server-actions/payment-import` разошёлся с реальным модулем при
  добавлении экшена — «No export defined on the mock» валит ВСЕ тесты файла
  (грабля этапа 5 в новой форме).
