Этот файл — то, по чему идёт заказчик. Колонка «Сухой прогон» заполнена мной

## Как поднять стенд

```bash
docker exec test-postgres psql -U testuser -d postgres -c 'CREATE DATABASE lk_otsfera_run29;'
```

`.env`: `DATABASE_URL` и `DIRECT_URL` на эту базу (**оба** — иначе миграции
уйдут в старую), `REDIS_URL` со своим номером базы, `APP_URL=http://localhost:3001`,
все `FEATURE_*` приёмки в `1`, `FAKE_BITRIX=1`, фиктивные `MANGO_API_KEY`/`MANGO_API_SALT`.

```bash
npx prisma migrate deploy && npm run prisma:seed
npm run dev -- -p 3001      # в одном окне
npm run worker:dev          # во втором — без него фоновые шаги не идут
```

Учётные записи — `admin@demo.local`, `leader@demo.local`, `manager@demo.local`,
`org@demo.local`, `partner@demo.local`, пароль у всех `Password123!`.

| 1.5–1.8 | Лид → сделка → КП → заказ | ✅ разделы «Лиды», «Сделки», «Воронка», «Заказы» открываются, связи между ними заведены этапами 1…7 |
| 1.9 | Ничего не вводится дважды | ✅ организация подставилась в диалог сама, по учётной записи клиента |

**Важно для заказчика.** Сообщение из кабинета **не появляется** во «Входящих в
работу» — и это правильно: отправитель известен (он сидит под своей учётной
записью), разбирать нечего, диалог сразу попадает в «Мессенджеры». Во «Входящие
в работу» падает то, что **неразобрано**: письмо с незнакомого адреса, звонок,
заявка с сайта.

**Два похожих названия в меню — так задумано.** «Входящие в работу»
(`/manager/intake`) — очередь разбора. «Входящие письма» (`/manager/inbox`) —
почта и мессенджеры. Оба термина есть в [глоссарии](../../glossary.md).

**Чего фикстура не покажет.** Объём и скорость живого портала. Это первый пункт
рисков спеки: настоящий Битрикс24 заказчика — десятки тысяч записей, и время
переноса меряется только на нём.

**Найдено и исправлено:** предпросмотр показывал «Лиды: создадим 1», а после
сопоставления стадий перенеслось 5 — список «Нужно решение» и счётчики были
снимком, сделанным **до** сопоставления, и не пересчитывались. Это тот самый
столбик, по которому человек решает, нажимать ли необратимую кнопку.
