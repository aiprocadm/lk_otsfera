- **Спека:** [2026-08-09-stage4-partner-cabinet-design.md](../specs/2026-08-09-stage4-partner-cabinet-design.md) — **подтверждена заказчиком 09.08.2026** («ок»)

- **Ветка:** `stage4-partner-cabinet` от `main` `1c6ffa8c`

## Подтверждённые решения

1. Кнопка «Добавить сотрудника» (`У-63`) — **этапом 5** вместе с `У-25`; поиск делаем сейчас.
2. Правку реквизитов организации получает **партнёр-администратор** — права расширяются в сервисе.
3. `/partner/team` остаётся **редиректом**, а не удаляется.

## Шаги

### Шаг 1. Права на реквизиты организации (`У-62`) — первым

`services/organization/requisites.ts`: helper `partnerAccess` — организация из
портфеля проверяется **по базе** (`Organization.partnerId`), а не по сессии
(список в токене устаревает, привязка — нет), плюс суженный скоуп
`assignedOrgIds`. Чтение — любому партнёрскому пользователю с доступом, запись —
только `partnerRole === 'admin'`.

Страж пишется в том же шаге: обе отказные ветки проверяют **и** код ответа,
**и** отсутствие записи в БД.

### Шаг 2. Вкладка «Настройки» организации (`У-61`, `У-62`)

`RequisitesCard` + `CustomerAccessSection` переезжают сюда; из общей области
карточки блок доступа убирается (`У-64`).

### Шаг 3. Настройки партнёра с вкладками (`У-60`)

Четыре вкладки; данные грузятся **только для активной**. «Команда» уходит из
`navByRole.partner`, `/partner/team` становится редиректом. Вкладка «Команда» —
только администратору; прямая ссылка от обычного пользователя открывает
«Профиль», а не пустой экран.

### Шаг 4. Поиск по сотрудникам (`У-63`)

Клиентский фильтр по имени/почте/должности + пустое состояние с подсказкой
(§15). Кнопка добавления — этапом 5.

### Шаг 5. Тесты и документы

Новые: страж прав на реквизиты, тест поиска. Переписаны: тест «Команды»
(теперь редирект), тесты меню партнёра, тесты обеих страниц карточки.
