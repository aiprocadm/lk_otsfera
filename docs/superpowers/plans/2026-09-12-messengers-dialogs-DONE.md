## Инварианты приёмки (спека §6) — как держатся

- Входящее в диалог ровно один раз — `MessengerMessage.inboundMessageId @unique`
  + повтор upsert при `P2002` (`messengers.dialog.test`, `messengers.appendInbound.integration`).
- Ответ виден в истории и из диалога, и из «Входящих писем» —
  `recordOutboundInDialog` в обоих путях (`services.inbound.sendReply.test`,
  `messengers.send.test`).
- Компания B невидима для A; ничей диалог забирает первый ответивший —
  `security.idor-messengers.integration`, `messengers.send.test`.
- Привязка диалога закрывает письма собеседника в очереди триажа и обучает
  контакт — `messengers.bind.test`.
- «Новый диалог» не принимает адрес от клиента — `messengers.start.test`,
  `server-actions.messengers.test`.
- Флаг `inbound_messaging` переключается из интерфейса — снят с
  `FEATURE_PREFIXES` (`featureFlags.route-gated.guardrail`,
  `docs.feature-flags-matrix`).
- Экраны: заголовок/подзаголовок/главная кнопка/пустое состояние, карточки на
  телефоне, термин «Мессенджеры» в словаре; исключение зеркала записано с
  причиной (`navigation.mirror.guardrail`).

## Вне объёма (спека §7) — не делалось, заказчику на решение

- Вложения (фото, файлы) из мессенджеров в диалоге — текст только.
- Новые адаптеры (VK, Viber): новый мессенджер = клиент + вебхук + строка в
  `MESSENGER_CHANNELS`; заводятся отдельной просьбой с кредами провайдера.
- Ответственный за диалог, статусы сверх «открыт/закрыт», шаблоны ответов.
- Зеркалирование переписки по заказу (`OrderThread`) в мессенджер и обратно.
- Привязка диалога к контакту из интерфейса (сервис умеет, форма — только
  организация).

## Что сделать на стенде/проде после раскатки

1. «Функции платформы» → переключатель «Мессенджеры» включён.
2. Один раз `npm run backfill:messengers -- --apply` — старые письма из
   мессенджеров лягут в диалоги (dry-run без флага показывает, сколько).
3. «Настройки → Интеграции → Подключение мессенджеров»: токены, секрет,
   регистрация вебхука, проверка связи.

## Уроки

- Курсорная пагинация со `skip: 1` пропускает живую строку, если строка-курсор
  выпала из условия выборки (обработанные письма исчезают из «ещё не
  сложенных»). Для очередей «взял → обработал → исчез» курсор не нужен:
  каждая пачка — снова «первые N».
- `renderToString` разделяет соседние текстовые узлы `<!-- -->` — проверки
  текста на строках с подстановками снимают комментарии перед сравнением.
- Стражи реестров (`pii.contexts`, `ui.empty-states`) ловят новые модули в
  полном прогоне, а не в целевом — полный `test:unit` перед PR обязателен.
