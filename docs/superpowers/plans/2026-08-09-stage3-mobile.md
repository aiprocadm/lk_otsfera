# Этап 3 «Мобильная версия» — план реализации

- **Спека:** [2026-08-09-stage3-mobile-design.md](../specs/2026-08-09-stage3-mobile-design.md) — **подтверждена заказчиком 09.08.2026** («ок»)
- **Требования:** `У-13`…`У-19`
- **Ветка:** `stage3-mobile` от `main` `13282310`

## Подтверждённые решения

1. Мобильные проекты Playwright переводятся на **390×844** (один набор эталонов).
2. Состав нижней панели — как в §4.2 спеки.
3. **Карточный режим делается всем восьми таблицам**, включая служебные
   админские («Синхронизация», «Очередь задач», «История импорта»).

## Шаги

### Шаг 1. Кто что показывает на телефоне (`У-15`)

`src/lib/navigation/mobileTabs.ts`: `MOBILE_TABS` — по четыре адреса на кабинет
и `mobileTabsFor(role, items)`, который выбирает из **уже отфильтрованного**
меню. Пункт, скрытый флагом или правами, во вкладках не появится.

Страж: каждый адрес из `MOBILE_TABS` существует в меню своей роли.

### Шаг 2. Сайдбар прячется, но переиспользуется (`У-13`)

`Sidebar` получает `variant`: `desktop` (по умолчанию) → `hidden md:flex`,
`panel` → видимый всегда, без `min-h-screen` и рамки. Внутрь выдвижной панели
кладётся **тот же** компонент, а не вторая разметка меню.

### Шаг 3. Бургер, панель и нижняя панель — один клиентский компонент (`У-14`…`У-16`)

`src/components/shell/mobile-nav.tsx` держит **общее состояние**: кнопка-бургер
в шапке, нижняя панель (`fixed bottom-0`, поэтому её положение не зависит от
места в дереве) и выдвижная панель на примитиве `Dialog`. Пятая вкладка «Ещё»
открывает ту же панель, что и бургер, — потому что состояние одно.

Кабинет заказчика передаёт в панель свой `OrgSidebar` (ссылки с `?org=`),
остальные — обычный `Sidebar`.

`partner/bottom-tab-bar.tsx` и `organization/bottom-tab-bar.tsx` удаляются.

### Шаг 4. Отступ один раз (`У-17`)

`pb-16 md:pb-0` в `AppShell` становится безусловным (панель теперь во всех
кабинетах), дубль из `partner/layout.tsx` убирается.

### Шаг 5. Восемь таблиц → карточки (`У-18`)

Примитив `src/components/ui/card-list.tsx` (`CardList` + `CardRow`), затем у
каждой из восьми таблиц: сама таблица получает `hidden md:block`, рядом
появляется `*-card-list.tsx` с `md:hidden`. Данные те же — переключение чистым
CSS, без JS и без определения устройства.

### Шаг 6. Playwright (`У-19`)

Мобильные проекты переименовываются в `mobile-*` и получают viewport
**390×844**. Добавляется функциональный `mobile-shell.spec.ts`: сайдбар скрыт,
нижняя панель видна, бургер открывает меню — это проверки поведения, они не
зависят от эталонных картинок.

### Шаг 7. Тесты и документы

Тесты на все новые компоненты; `AUDIT.md`, `STATUS.md`, `CHANGELOG.md`.

## Что осталось владельцу

Эталоны `npm run e2e:visual` перегенерировать **один раз** после этого этапа:
их сдвинул этап 2 (вид сайдбара) и сдвинет смена viewport. В CI визуальные
тесты не входят.
