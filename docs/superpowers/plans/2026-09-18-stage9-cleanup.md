# Этап 9 «Очистка и упрощение» — план работ

**Спека:** [2026-09-18-stage9-cleanup-design.md](../specs/2026-09-18-stage9-cleanup-design.md)
**Требования:** `У-259`…`У-267` · **Дефекты:** `Д-41`, `Д-42`, `Д-43`, `Д-47`, `Д-49`
**REQUIRED SUB-SKILL:** superpowers:subagent-driven-development

Порядок PR нарушать нельзя: `У-261` — два PR (отчёт до миграции, §5 ТЗ), флаги — пачками по три.
Каждый PR: `base: main`, зелёные `typecheck` ×2 / `lint` / `boundaries` / `deadcode` / `dup:check` /
`format:check` / `tz:status`. При правках схемы и сервисов — `npm run gate` (живого Postgres в
сессии нет, поднимается Docker-контейнер). Каждый новый страж — **проверен мутацией** (поломка
вносится и откатывается из `.bak`, а не `git checkout`).

**Про полный `test:unit`.** Слой большой (≈1424 файла, ≈16 000 тестов), а машина занята
параллельными задачами — один прогон идёт больше часа. Десять прогонов подряд в этап не
помещаются, поэтому проверка распределена по риску:

| PR | Что гоняем | Почему так |
|---|---|---|
| 1, 2, 5, 6, 10 | Затронутые файлы + все стражи + 7 гейтов | Правки локальные: документы, один читатель, новые стражи. Поломка соседнего теста отсюда не следует |
| 3, 4, 7, 8, 9 | **Полный `test:unit`** (+ `gate` у 3 и 4) | Удаление модели и снятие флага трогают десятки файлов сразу — это ровно тот случай, ради которого полный прогон и нужен |
| Перед close-out | **Полный `test:unit` + `test:integration`** | Итоговое доказательство этапа |

Это не ослабление гейта, а распределение одного и того же прогона по местам, где он что-то
доказывает. Перед закрытием этапа полный прогон обязателен в любом случае.
