**Границы PR-3:** карточки организации, партнёра и сотрудника + перевод карточки
заявки на общий компонент (иначе новые семь типов на заявке отрисовались бы
текстовым полем). Карточка документа — PR-4: её в системе не существует, это
отдельный экран в пяти кабинетах.

## Задачи

### 1. Общий компонент секции

- [x] `components/custom-fields/entity-custom-fields.tsx` — все 12 типов:
      `textarea`, `money` (текст + `inputMode=decimal`, не `type=number` —
      иначе теряются копейки), `datetime`, `multiselect` (галочки),
      `phone`/`email`/`url`, плюс прежние пять.
- [x] Подсказка (`helpText`) под контролом и в режиме показа.
- [x] **Право правки — по каждому полю** (`definition.editable` с сервера).
      Поле без права показывается значением, а не заблокированным контролом:
      заблокированный контрол читается как «сломалось», а не «не ваше».
- [x] Секция не рендерится, если полей нет; без единого правимого поля —
      показ без формы.

### 2. Server action на пять сущностей

- [x] `saveCustomFieldsAction(entityType, entityId, values)` вместо
      заказо-специфичного; revalidate путей карточки во всех кабинетах, где
      она живёт (иначе соседний кабинет покажет старое значение из кэша).
- [x] `saveOrderCustomFieldsAction` оставлен тонкой обёрткой — вызовы на
      деталке заказа и их регрессы не переписываются.

### 3. Точки монтирования

- [x] `admin/organizations/[id]`, `manager/organizations/[id]` — организация.
- [x] `admin/partners/[id]` — партнёр (у менеджера карточки партнёра нет,
      решение Q4).
- [x] `manager/students/[id]`, `organization/students/[id]` — сотрудник.
- [x] Заявка: `order-custom-fields.tsx` стал тонким адаптером над общим
      компонентом; legacy-проп `editable` только СУЖАЕТ права, никогда не
      расширяет.

### 4. Тесты

- [x] Компонент: контролы всех 12 типов, подсказка, смешанный режим
      (правимое + только для чтения), сохранение (сущность + запись +
      значения), очистка пустого в `null`, множественный выбор (отметка,
      снятие, битое значение), отказ сервера.
- [x] `formatValue`: прочерк, «Да/Нет», рубль, список через запятую, дата+время,
      битый JSON не роняет карточку.
- [x] Страницы: в пяти тестах карточек замокан `getValuesForEntity` (иначе
      сервис лезет в реальный prisma).
- [x] 100 % покрытие новых файлов (§6 CLAUDE.md).

## Найдено по ходу

- **Мок сервиса в тестах карточек — обычной функцией, не `vi.fn()`.** В этих
  файлах есть `resetAllMocks`, который снёс бы заготовленный ответ, и страница
  падала бы на `Cannot read properties of undefined (reading 'ok')`.
- **Открытый вопрос заказчику остаётся:** руководитель без закреплённых
  организаций не открывает карточку организации (`canManagerAccessOrg` не
  применяет лидер-инвариант C8), поэтому и поля организации он там не увидит.
  Политика доступа этим PR **не менялась** — это выходило бы за §11.
