# Этап 2 «Реестр значков + единый шелл» — план реализации

- **Спека:** [2026-08-09-stage2-nav-icons-shell-design.md](../specs/2026-08-09-stage2-nav-icons-shell-design.md) — **подтверждена заказчиком 09.08.2026** («ок»)
- **Требования:** `У-5`…`У-12`
- **Ветка:** `stage2-nav-icons-shell` от `main` `270d3a5e`

## Подтверждённые решения

1. **Переименования пунктов меню** приняты полностью (таблица §4.2 спеки).
2. Значки остаются **эмодзи**.
3. Тёмная шапка кабинета партнёра и слушателя **сохраняется**.

## Шаги

### Шаг 1. Реестр значков (`У-5`)

`src/lib/navigation/icons.ts`: `NAV_ICONS` + тип `IconKey` + `navIcon()`.
Ключ — семантика раздела. Включены все 23 ключа, названные в `У-5` поимённо.

### Шаг 2. Меню на семантические ключи (`У-6`, `У-7`)

В `NavItem` поле `icon?: string` → `iconKey: IconKey` (**обязательное**).
Все 92 пункта переведены; партнёр (11 пунктов) и слушатель (1) впервые
получают значки.

### Шаг 3. Разведение конфликтов и переименования (`У-8`)

Значки: «Команда» → 👔, «Кабинет руководителя» → 🧭, «Кабинет слушателя» → 🎒,
«Партнёры» → 🏬, «Организации» → 🏢 во всех ролях, «Загрузка из 1С» → 📤,
«Импорт оплат» → 💳, «Импорт выписки (сч. 51)» → 🏦.

Названия: «Сводка» → «Главная»; «Обращения клиентов» и «Мои заявки» →
«Обращения»; `/manager/inbox` → «Входящие письма»; «Загрузка Excel» →
«Загрузка из 1С».

**Заодно правятся заголовки страниц и глоссарий** — иначе меню говорит одно, а
экран другое, и §15 («где я») не выполняется. Затронуты `h1` пяти страниц
обращений, `h1` входящей почты, `lib/navigation/breadcrumbs.ts` и
`docs/glossary.md`.

### Шаг 4. Страж (`У-9`)

`src/__tests__/navigation.icons.guardrail.test.ts` — инвариант в обе стороны +
проверки реестра (нет неиспользуемых ключей, два ключа не делят эмодзи, все
ключи `У-5` заведены).

### Шаг 5. Единый каркас (`У-10`, `У-11`, `У-12`)

`src/components/shell/{app-shell,sidebar}.tsx`. Удаляются `admin-app-shell`,
`admin-sidebar`, `manager-app-shell`, `manager-sidebar`, `leader-app-shell`,
`leader-sidebar`; их layout'ы собирают каркас сами.

`org-app-shell` / `org-sidebar` и `dashboard/app-shell` остаются **тонкими
переходниками**: org-кабинет не имеет общего layout-шелла (активная организация
резолвится из `searchParams`, поэтому каждая из 17 страниц оборачивает себя
сама), а `/student` — отдельная точка входа с двумя ветками.

### Шаг 6. Тесты

Шесть тестов удалённых шеллов заменяются тремя: `components.shell-app-shell`,
`components.shell-sidebar`, `pages.cabinet-layouts`. Проверка фильтра
«Настройки» у руководителя переезжает из `cov.gap-components-misc` в
`pages.cabinet-layouts` (файл, где эта логика теперь живёт).

### Шаг 7. Документы

`AUDIT.md` (`У-5`…`У-12` → `✅`), `STATUS.md`, `CHANGELOG.md`, `docs/glossary.md`.

## Что осталось владельцу

**Эталоны визуальных тестов (`npm run e2e:visual`) не перегенерированы** —
для этого нужны seed-база и запущенный `npm run dev`. Внешний вид сайдбара
изменился во всех кабинетах, поэтому 38 эталонов ожидаемо разойдутся. В CI
визуальные тесты не входят, красной сборки не будет.
