## Решения, закреплённые в коде

1. **`mayImportOneC` — в `managerPolicy.ts`**: guard-тест матрицы читает экспорты
   файла и потребовал строку-фиксацию (шесть ролей; право не зависит от
   `companyId`). Файл `docs/tz/2026-07-30-role-access-matrix.md` из буквы Т-25
   не заводился — матрица живёт в тесте (решение 30.07, §8.1 спеки).
2. **`LegacyRoute.cabinet`** — карта редиректов выводила кабинет из префикса
   пути; `/manager/import` руководителя должен уезжать в **leader**-хаб, поэтому
   у legacy-записи появился явный кабинет. Дубль в `next.config.mjs` пополнен —
   существующий drift-тест сверяет.
3. **Шлюзы `/manager/import` и `/manager/payments-import` рендерят
   leader-страницу** как fallback (паттерн §2b): её гард отбивает обычного
   менеджера в `/forbidden` при любом состоянии флага — отдельный
   `requireManagerLeader` в шлюзе не нужен.
4. **`OneCTabs` получил проп `cabinet`** (дефолт `admin` — существующие
   использования не менялись).
5. **Очередь разбора выписки** (`resolve-queue`/`resolve-picker`) осталась на
   staff-предикате (§8.2 спеки): Т-26 называет только два файла импорта, права
   кнопок очереди — этап 10.

## Грабли этого этапа

- **Тесты, жившие на «менеджер может импортировать»**, оказались в трёх слоях:
  unit (`import.index.unit` — audit-ветка на менеджере), integration
  (`import.unified` Test 3 — скоуп-проверка) и cov-слое
  (`cov.import-commit` — «admits the manager role»). Скоуп-проверку C8 нельзя
  просто удалить — переведена на руководителя чужой компании (инвариант
  сохранён, право — по-новому).
- Канон меню менеджера в `featureFlags.manager.test.ts` держит жёсткий счётчик
  пунктов (11 → 9) — грабля «жёсткие счётчики меню» стрельнула четвёртый раз.
