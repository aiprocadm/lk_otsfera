## Настоящие дефекты и находки (решение Q4 — чинили сразу)

1. **Фильтр заявок по статусу справочника (§10, этап 2) не проверялся ни одним
   тестом** — закреплён интеграционным тестом на живом Postgres.
2. **Гонка запросов в подсказке дублей по ИНН**: опоздавший ответ по прежнему
   ИНН мог подменить плашку чужими дублями. Защита была, теста не было.
3. **Отказ сохранения ревалидировал страницу** (`server-actions/{requisites,intake}`):
   человек видел «обновлённый» экран со старыми данными и уходил уверенным,
   что сохранил.
4. **Ошибка базы маскировалась под ошибку пользователя** («проверьте
   реквизиты») и не попадала в мониторинг — ветка `throw` не проверялась ни в
   одном из четырёх сервисов реквизитов.
5. **Статус «письмо отправлено» при выключенной почте** — проверялся только у
   партнёров; организация/менеджер/слушатель могли ждать письмо, которого нет.
6. **Ответ на вопрос из кабинета** — единственный канал доставки ответа
   клиенту — не проверялся вовсе.
7. **Смена ключа шифрования** секретов интеграций: тихий откат в env был в
   коде, но не был закреплён — его поломка обрывала бы почту и телефонию.
8. **Автозаполнение по подсказке ДаДаты** не проверялось ни в одной из четырёх
   форм — основной способ заполнить реквизиты.
9. **Отказ запроса реквизитов у клиента показывался успехом** — причём название
   существующего теста обещало эту проверку.
10. **Дата рождения из Excel-импорта** без приведения к формату поля терялась бы
    молча.

## v8 ignore, добавленные программой (все — с причиной в комментарии)

| Где | Причина |
|---|---|
| `partner/invite-member-form.tsx` | guard `!invite` перед копированием — кнопка существует только при invite; нужен для сужения типа |
| `inbound/cabinetQuestion.ts` | `split().pop() ?? 'file'` — split всегда даёт минимум один элемент; нужен для типа |
| `documents/generate.ts` | хвост `\|\| ''` в displayName — обязательность названий проверена выше |
| `deals/deal-dialog.tsx` | половинка `!targetId` — блок заметок рендерится только в режиме редактирования |
| `deals/deal-board.tsx` | guard `!wonFor` — кнопка подтверждения существует только при открытом диалоге |
| `enrollment-wizard.tsx` | guard двойного события контролируемого чекбокса |
| `manager/organizationCard.ts` | пустой список при отказе listCertificates — сервис не возвращает ошибок для read-скоупа; вынесен в отдельную строку, т.к. в тернарнике внутри объекта пометка не действует |

Попутно выяснилось, что **многострочный `/* v8 ignore */` не распознаётся
провайдером** — только однострочный. Две старые пометки не работали; починены.

## Грабли для будущих правок

- **Мерить все четыре метрики.** Проверка только statements/branches уже давала
  ложное «покрыто» — functions выпадали.
- Пороги активны **только в полном прогоне** (`npm run test:coverage`, живой
  Postgres, ~30 мин); частичные режимы порог не проверяют — поэтому краснота
  и жила незамеченной.
- Отчёт печатает проценты округлёнными, сравнение идёт по точному значению —
  порог «ровно как в отчёте» может дать ложную красноту.
- Адресная проверка файла без полного прогона:
  `npx vitest run --coverage --coverage.include='<файл>' <его тесты>`.
