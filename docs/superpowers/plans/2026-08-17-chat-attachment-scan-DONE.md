## Решения, которые НЕ переизобретать

- Default колонки — `'none'` (не `'pending'`): default pending пометил бы
  все сообщения без вложений и завалил sweep.
- Нового процессора НЕТ — kind в общем `scan-document.ts`; guardrail
  полноты процессоров не задет.
- Скан-инфраструктура вне флага `chat` (иначе выключение флага заморозило
  бы вложения в pending навсегда).
- Гейт в сервисе — `scanStatus !== 'clean'` → `not_ready` (а не перечисление
  pending|error): покрывает и гипотетический none-с-вложением.
- Legacy-строки бэкфилла Comment→Message (пути не `chat/…`) остаются
  `'none'`: их скачивание отрезано префикс-гардом, файлы сканируются в
  канале Document.

## Грабля, которую словил и починил в том же PR

`sendMessage` стал звать `getQueue` → три тестовых файла, зовущих настоящий
сервис (unit ×2 + integration), зависли бы на BullMQ без Redis — добавлен
мок `@/lib/jobs/queues` (канон: services.certificateScans.integration).
Тест формы `BackfillResult` ломается любым новым ключом — это и есть страж
полноты sweep, правится вместе с ключом.
