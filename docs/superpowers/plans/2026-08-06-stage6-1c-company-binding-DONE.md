## Решения, закреплённые в коде

1. **Одна точка выбора компании** — create-ветка writer'а; скоуп `company`
   побеждает всегда (integration-тест: `createCompanyId` с чужой компанией
   проигрывает компании руководителя).
2. **Воркер без конфига — построчная ошибка, не остановка** (решение §4.3
   спеки, подтверждено «ок»): полная остановка молча заморозила бы и
   обновления существующих организаций.
3. **Фильтр `companyIds`** в сервисе бэкфилла — страховка точечного прогона и
   обязательна для integration-тестов на общей базе (там могут жить чужие
   сироты, которых тест трогать не имеет права).
4. **Заказы двигаются по ссылке на компанию-сироту** (`companyId = сирота`),
   а не «все заказы организации» — заказ, уже живущий в правильной компании,
   не трогается.
5. UI: селект «Компания для новых организаций» только при >1 компании; смена
   выбора сбрасывает посчитанный план (он считался для другой компании).

## Грабли этого этапа

- **`cov.worker-sync.test.ts` — integration-слой**, хотя лежит рядом с
  unit-«cov»-файлами: содержит `new PrismaClient(`. Прогонять с живым PG.
- Тесты, жившие на минте Company, перечислены заранее в спеке — волна прошла
  по списку без сюрпризов: stage4/stage5 integration (своя Company +
  `companyId` в args — на общей базе много компаний, дефолт не сработает),
  unified (companyId в args), unit-моки `$transaction`/`company: { create` в
  трёх файлах, инвариант C8.
- В integration-тесте бэкфилла decoy «с пользователем» цепляет тестового
  юзера к компании — в afterAll обязательно `updateMany companyId: null` до
  удаления компаний, иначе P2003 при падении теста посреди сцены.
