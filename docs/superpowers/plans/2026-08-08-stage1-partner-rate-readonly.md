# Этап 1 «Хотфикс партнёрской ставки комиссии» — план реализации

- **Спека:** [2026-08-08-stage1-partner-rate-readonly-design.md](../specs/2026-08-08-stage1-partner-rate-readonly-design.md) — **подтверждена заказчиком 08.08.2026**

- **Ветка:** `worktree-stage1-partner-rate` от `main` `0cad2e84`

## Ответы заказчика на три вопроса §8 спеки

| Вопрос | Ответ заказчика | Следствие для кода |
|---|---|---|
| 1. Роут `PUT …/rate` закрыть или удалить? | **Закрыть** | Роут остаётся, гард меняется на `requireAdmin`; роль `partner` получает `403` при любом `partnerRole` |
| 2. Показывать ставку всегда или только особую? | **Только особую, как сейчас** | Условие показа плашки в `OrgCardHeader` **не меняется**; `getOrgCard` **не расширяется** — поля `effectiveCommissionRate` не будет. Добавляется только пометка «назначает учебный центр» |
| 3. Вкладку «Настройки» оставить или скрыть? | **Оставить с объяснением** | Страница получает заголовок, подзаголовок и пустое состояние (§15) |

**Зафиксированное следствие ответа №2:** партнёр, у которого индивидуальной
ставки нет, не увидит на экране **никакой** ставки — базовая ставка партнёра ему
не показывается. Это осознанное решение заказчика; в `AUDIT.md` вердикт `У-3`
сопровождается этой оговоркой, чтобы следующая сверка не сочла это расхождением.

## Шаги

### Шаг 1. `У-1` — убрать форму у партнёра

1. Удалить `src/components/partner/rate-override-form.tsx`.
2. Удалить `src/__tests__/components.partner-rate-override-form.test.tsx`.
3. В `src/app/partner/portfolio/[orgId]/settings/page.tsx` убрать импорт и рендер.

### Шаг 2. `У-1` + §15 — страница настроек не остаётся пустой

В `settings/page.tsx` вместо формы:

- заголовок раздела «Настройки организации»;
- подзаголовок одной строкой: «Условия работы по этой организации. Ставку
  комиссии назначает учебный центр.»;
- пустое состояние с объяснением и **ссылкой-действием** «Написать менеджеру» на
  существующую вкладку комментариев `?tab=comments` (новых экранов не заводим).

### Шаг 3. `У-2` — закрыть роут для роли `partner`

`src/app/api/partner/portfolio/[orgId]/rate/route.ts`:

- `requirePartnerAdmin` → `requireAdmin` (оба из `@/lib/auth/guard`);
- убрать `canPartnerAccessOrg` — предикат по определению возвращает `false` для
  не-партнёра (`policy.ts:161`), с админской сессией роут был бы мёртв;
- вместо ручного разбора `set`/`clear` вызвать готовый
  `applyOrgRateOverride` из `services/admin/orgRateOverride.ts`: он **сам**
  разрешает `partnerId` по организации (в админской сессии `partnerId` нет) и
  сам выбирает операцию. Своей логики не пишем.
- коды ответа: `not_found` → `404`, остальное (`validation`,
  `rate_out_of_range`) → `422`; успех — `204`, как было.

Числа: роут принимает долю (`0.085`), `applyOrgRateOverride` — проценты, поэтому
`rate * 100`. Колонка `Organization.partnerCommissionRate` — `Decimal(6,4)`,
поэтому обратное деление не даёт «плавающих» копеек.

### Шаг 4. `У-3` — пометка «назначает учебный центр»

`src/components/partner/org-card-header.tsx`: в существующую плашку добавить
строку-пометку. Условие показа плашки **не трогаем** (ответ заказчика №2).

### Шаг 5. `У-4` — тест-страж

`src/__tests__/api.partner.portfolio.rate.test.ts` переписать целиком:

- `partner` + `partnerRole: 'admin'` → `403`;
- `partner` + `partnerRole: 'manager'` → `403`;
- **в обоих случаях** `prisma.$transaction`, `organization.update` и
  `organizationCommissionRateChange.create` **не вызваны** — проверяем оба факта,
  как требует шапка `STATUS.md`;
- сервис `rateOverride` в этом файле **не мокается**: если гард однажды
  пропустит партнёра, вызов уйдёт в замоканную призму и страж это увидит;
- `admin` → `204` (роут жив для внутренних ролей);
- сохранить проверки `401`, `400`, `404`, `422`.

### Шаг 6. Тесты страницы и карточки

- `pages.partner-portfolio-orgid-settings.test.tsx`: полей ввода ставки нет,
  подзаголовок и ссылка-действие на месте;
- `components.partner-org-card-header.test.tsx`: пометка есть при индивидуальной
  ставке, плашки нет при `partnerCommissionRate: null`.
