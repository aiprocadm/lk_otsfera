## Отклонения от ТЗ (осознанные)

1. **Редиректы временные (307), а не постоянные (308).** ТЗ §5.1 просит
   постоянные. 308 браузер кэширует навсегда: если после раскатки понадобится
   выключить флаг `settings_hub`, у уже заходивших пользователей навигация
   останется мёртвой. Перевод на 308 — шагом снятия флага после приёмки.
2. **`/admin/settings` был занят** работающей страницей личных настроек. Её
   содержимое разложено по четырём разделам хаба (спека §3.4), ничего не
   потеряно. ТЗ этот случай не описывал.
3. **Тест полноты «по enum»** (ТЗ §6.4.2) буквально неисполним: `action` и
   `entity` в Prisma — свободные строки. Вместо enum введены рантайм-реестры,
   и `AuditRecord.action` типизирован объединением — теперь незарегистрированное
   событие не компилируется. Это строже, чем просило ТЗ.
4. **Страницы 1С не объединены** в одну — ТЗ §10 прямо это разрешает, если
   объединение потребует правки логики. Они стали двумя вкладками одного
   подраздела.
5. **«Дедушкина оговорка» в правах:** профиль доступа, где не размечен ни один
   `settings.*`-код, сохраняет прежний доступ. Иначе включение новой модели
   молча отняло бы доступ у всех ранее заведённых профилей.

## Слияние с main по ходу работы

В `main` параллельно влили аудит A1 (вынос запросов Prisma из страниц в
сервис-слой, PR #304/#305). Конфликт по двум файлам разрешён в пользу
рефакторинга main: их новые тела перенесены в хаб, поверх наложен гард раздела.

## Найдено и починено попутно

- Боковая навигация подсвечивала два пункта разом на вложенной вкладке
  (наивный `startsWith` вместо самого длинного совпадения).
- Примитив крошек ставил `aria-current="page"` любой крошке без ссылки, а не
  только последней — промежуточная группа врала скринридеру.
