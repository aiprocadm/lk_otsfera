## PR-1 «Фундамент» — `У-131`, `У-132`, `У-133`

- [x] **`У-133` (дефект `Д-37`): снапшот флагов праймится до первого запроса.**
      Праймил его только `getSession()`, а `api/auth/login` и `api/auth/2fa/*`
      работают ДО всякой сессии — получался замкнутый круг: чтобы 2FA
      включилась, надо войти; чтобы войти по новым правилам, нужна включённая
      2FA. Прайм добавлен в `instrumentation.ts` (старт процесса), в воркер
      (у процессоров своей сессии нет) и в сами три роута. Прайм дешёвый —
      внутри TTL 30 с, лишнего запроса на каждый вход не будет.
- [x] **`У-132` (дефект `Д-36`): ключ шифрования обязателен и виден заранее.**
      `APP_ENCRYPTION_KEY` стал обязательным в production-схеме `env.ts`
      (минимум 16 — та же граница, что в `resolveKey()`, шире ставить нельзя,
      иначе схема и рантайм разойдутся) и описан в обоих примерах окружения.
      На странице интеграций баннер стоит **до форм**: раньше об отсутствии
      ключа человек узнавал, только нажав «Сохранить», то есть заполнив форму
      секретами впустую. `/api/health` показывает состояние ключа — но **не**
      включает его в `status`: иначе балансировщик снял бы живой сервер из-за
      настройки.
- [x] **`У-131` (дефект `Д-35`): значение можно вернуть к серверному.**
      Введённое в интерфейсе значение перекрывает env, и убрать его было
      нельзя: пустое поле у секрета означает «не менять», а не «стереть».
      Появилось действие `resetSettingToServerValueAction` (ключ проверяется
      по реестру — чужая строка из формы не должна удалять произвольную
      запись) и кнопка «использовать значение сервера». Кнопка показывается
      **только при реальном перекрытии** (`source === 'db'`): предлагать
      «вернуть серверное» там, где ничего не перекрыто, — врать человеку.
- [x] `whatsapp.channelId` перестал быть секретом: это адрес канала, а не
      секрет, и пока он был помечен секретом, форма его не показывала.
- [x] **Попутно найдено и починено:** после снятия пометки «секрет» строка,
      записанная в базу ЗАШИФРОВАННОЙ, показалась бы в форме шифротекстом.
      `getSettingsView` теперь расшифровывает по флагу самой строки, а не по
      текущей спецификации. Само по себе это в требованиях не описано —
      но без этого `У-131` ломает то, что чинит.
- [x] Стражи проверены **девятью** мутациями. Три проверки пришлось
      ужесточить — см. ниже.

### Уроки PR-1 (три слабых стража из девяти мутаций)

1. **«Слово осталось в объявлении».** Проверка «в `instrumentation.ts` есть
   `primeFeatureFlagCache`» проходила и после удаления ВЫЗОВА: идентификатор
   остаётся внутри самой функции. Проверять надо вызов
   (`await primeFeatureFlagsOnBoot();`).
2. **То же во второй раз.** `/api/health` «показывает ключ» — проверка ловила
   `const secretsKey = …`, то есть подсчёт без отдачи в ответ. Ужесточено до
   `checks: { … secretsKey }`.
3. **Срез «первые N символов» захватывает соседа.** Проверка «channelId не
   секрет» брала 400 символов после имени ключа и находила `isSecret: false`
   у СЛЕДУЮЩЕЙ настройки. Режем ровно по концу записи.

Общее правило, третий этап подряд: **зелёный страж ничего не доказывает.**

## PR-2 «Телефония и секреты вебхуков» — `У-123`, `У-124`

- [x] **`У-124` (дефект `Д-38`): `telephony_mango` снят с `FEATURE_PREFIXES`.**
      Флаг читало edge-middleware, у которого нет базы: **выключить** телефонию
      из интерфейса получалось, а **включить** — нет, middleware отдавал 404
      раньше, чем страница успевала заглянуть в базу. Переключатель создавал
      иллюзию управления. Снятие с edge-гейта автоматически делает флаг
      редактируемым в «Функциях платформы» (`editable: !isRouteGatedFlag`).
- [x] Взамен раздел закрывают **три серверные точки**: страница
      (`isFeatureEnabled` + `notFound`), пункт меню и гард роута звонков.
      Страж проверяет **каждый** файл `route.ts` под `api/manager/calls` —
      сейчас он один, но следующий появится без гарда, и никто не заметит.
- [x] **Оба экрана про телефонию читают флаг одинаково.** В `integrations.ts`
      стояло сырое `process.env.FEATURE_TELEPHONY_MANGO`, в
      `integrationsHealth.ts` — `isFeatureEnabled`. После переключения из
      интерфейса светофор и карточка статуса показали бы разное.
- [x] Адаптер, список разрешённых адресов вебхука и задержка поллинга
      статистики стали полями формы (`mango.adapter`, `mango.allowedIps`,
      `mango.statsPollDelayMs`) с обычным приоритетом «база → env → умолчание».
      Адреса Mango меняет без нашего участия — раньше на это требовался деплой.
- [x] Смена адаптера **сбрасывает его кэш**: он живёт на весь процесс, и без
      сброса переключение «тестовый ↔ боевой» ждало бы перезапуска.
- [x] **`У-123`: секреты вебхуков** Telegram, Max и WhatsApp переехали в
      реестр настроек; роуты сверяют их через `getSettingValue`, индикатор
      «задан» читает базу. Появились кнопки «Сгенерировать секрет» (значение
      показывается **один раз** — дальше оно зашифровано) и «Зарегистрировать
      вебхук».
- [x] Кнопка регистрации показывается **только** там, где у провайдера есть на
      это API. У WhatsApp-агрегатора адрес задаётся в его личном кабинете, и
      кнопка, которая ничего не делает, была бы хуже её отсутствия.
- [x] Соль Mango (`apiSalt`) в генерируемые секреты **не входит**: её выдаёт
      провайдер, придумать её на своей стороне нельзя. Закреплено стражем.
- [x] Стражи проверены **десятью** мутациями.

### Что нашлось по дороге

- **`'__proto__' in obj` истинно у любого объекта.** Проверка «известный ли
  ключ» через `in` пропускала строку `__proto__` — и в новом коде, и в
  `resetSettingToServerValueAction` из PR-1, где она охраняет **удаление**
  записи настроек. Обе переведены на `Object.hasOwn`. Нашёл написанный тест,
  а не ревью.
- Две проверки самого стража оказались ложными: страница гардит через
  `isFeatureEnabled` + `notFound` (а не `notFoundIfDisabled`), а имя
  переменной осталось в комментарии сервиса. Проверять надо **чтение**
  (`process.env.X`), а не упоминание имени.
- **Перенос чтения в базу уронил 11 файлов тестов** — и это правильный
  сигнал, а не помеха. Роуты вебхуков мокали `prisma` пустым объектом, и
  `getSettingValue` падал на `integrationSetting.findUnique`. Мок дополнен
  так, чтобы база отвечала «пусто» — тогда срабатывает запасное чтение из
  переменной окружения, которое тест и выставляет: заодно проверяется сам
  приоритет «база, затем env».
- **Дублированный список ключей в тесте страницы разъехался** с настоящим.
  Он был скопирован в тест, страница добавила три ключа, и `byKey()` упал на
  `undefined`. Мок переписан так, чтобы отвечать на то, что страница
  **реально спросила**, — копия списка удалена, разъезжаться больше нечему.
