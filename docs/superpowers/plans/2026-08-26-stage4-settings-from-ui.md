## PR-1 «Фундамент» — `У-131`, `У-132`, `У-133`

- [x] **`У-133` (дефект `Д-37`): снапшот флагов праймится до первого запроса.**
      Праймил его только `getSession()`, а `api/auth/login` и `api/auth/2fa/*`
      работают ДО всякой сессии — получался замкнутый круг: чтобы 2FA
      включилась, надо войти; чтобы войти по новым правилам, нужна включённая
      2FA. Прайм добавлен в `instrumentation.ts` (старт процесса), в воркер
      (у процессоров своей сессии нет) и в сами три роута. Прайм дешёвый —
      внутри TTL 30 с, лишнего запроса на каждый вход не будет.
- [x] **`У-132` (дефект `Д-36`): ключ шифрования обязателен и виден заранее.**
      `APP_ENCRYPTION_KEY` стал обязательным в production-схеме `env.ts`
      (минимум 16 — та же граница, что в `resolveKey()`, шире ставить нельзя,
      иначе схема и рантайм разойдутся) и описан в обоих примерах окружения.
      На странице интеграций баннер стоит **до форм**: раньше об отсутствии
      ключа человек узнавал, только нажав «Сохранить», то есть заполнив форму
      секретами впустую. `/api/health` показывает состояние ключа — но **не**
      включает его в `status`: иначе балансировщик снял бы живой сервер из-за
      настройки.
- [x] **`У-131` (дефект `Д-35`): значение можно вернуть к серверному.**
      Введённое в интерфейсе значение перекрывает env, и убрать его было
      нельзя: пустое поле у секрета означает «не менять», а не «стереть».
      Появилось действие `resetSettingToServerValueAction` (ключ проверяется
      по реестру — чужая строка из формы не должна удалять произвольную
      запись) и кнопка «использовать значение сервера». Кнопка показывается
      **только при реальном перекрытии** (`source === 'db'`): предлагать
      «вернуть серверное» там, где ничего не перекрыто, — врать человеку.
- [x] `whatsapp.channelId` перестал быть секретом: это адрес канала, а не
      секрет, и пока он был помечен секретом, форма его не показывала.
- [x] **Попутно найдено и починено:** после снятия пометки «секрет» строка,
      записанная в базу ЗАШИФРОВАННОЙ, показалась бы в форме шифротекстом.
      `getSettingsView` теперь расшифровывает по флагу самой строки, а не по
      текущей спецификации. Само по себе это в требованиях не описано —
      но без этого `У-131` ломает то, что чинит.
- [x] Стражи проверены **девятью** мутациями. Три проверки пришлось
      ужесточить — см. ниже.

### Уроки PR-1 (три слабых стража из девяти мутаций)

1. **«Слово осталось в объявлении».** Проверка «в `instrumentation.ts` есть
   `primeFeatureFlagCache`» проходила и после удаления ВЫЗОВА: идентификатор
   остаётся внутри самой функции. Проверять надо вызов
   (`await primeFeatureFlagsOnBoot();`).
2. **То же во второй раз.** `/api/health` «показывает ключ» — проверка ловила
   `const secretsKey = …`, то есть подсчёт без отдачи в ответ. Ужесточено до
   `checks: { … secretsKey }`.
3. **Срез «первые N символов» захватывает соседа.** Проверка «channelId не
   секрет» брала 400 символов после имени ключа и находила `isSecret: false`
   у СЛЕДУЮЩЕЙ настройки. Режем ровно по концу записи.

Общее правило, третий этап подряд: **зелёный страж ничего не доказывает.**
