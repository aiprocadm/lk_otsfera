## Что было найдено сверх ТЗ

- **Пробел разбивки §9.** Модуль 5 («чек-лист готовности → Передано») не входил
  ни в один из 11 этапов, хотя §4 описывает его как часть сквозного потока.
  Всплыло на ФТ-15.3: блок «Готово к передаче» определён как «чек-лист закрыт,
  передача не нажата» — а нажимать было нечего. По решению заказчика заведён
  этап 12; этап 11 приостановлен после PR-1 и продолжен после.
- **Две реальные утечки** (этап 10): открытый API партнёрских лидов отдавал
  `assignedManagerName`, а DTO обращения — `convertedLeadId` (id внутреннего
  лида). Обе закрыты, обе покрыты негативными тестами.
- **Неработающий пункт чек-листа** (этап 12): «загружен скан удостоверения»
  нельзя было закрыть через интерфейс — поле заполнялось только через API.
  Учебный заказ физически не мог стать «готовым». Закрыто PR-2 этапа 12.
- **Мёртвый `enum NotificationType`** в схеме: не связан ни с одной колонкой,
  в коде не упоминался, состав разошёлся с реальностью (8 против 29 живых
  типов). Удалён миграцией, источник правды — реестр в коде.

## ~~Остаток программы~~ — закрыт 28.07.2026

**ФТ-15.9 закрыт: эталоны переведены на Linux** (решение заказчика — своей
Windows-машины для прогона нет). Что сделано:

- **38 эталонов вместо 10** — покрытие выросло вчетверо: у экранов админа,
  руководителя, менеджера, партнёра и лендинга слушателя эталонов не было вовсе.
- **Мобильные проекты переведены с WebKit на Chromium.** Пресет
  `devices['iPhone 13']` тянет за собой движок Safari, а он требует системных
  библиотек и прав администратора. Проверяется **адаптив** (375×667, `isMobile`),
  а не движок — на Linux и в CI это единственный работающий вариант.
- **Пин полного Chrome for Testing** (`channel: 'chromium'`) вместо
  chrome-headless-shell: shell иначе обрабатывает фокус.
- Полный `npm run e2e:visual` — **зелёный** (38 снимков + focus-trap).

**Побочная находка — настоящий дефект доступности.** Focus-trap-спека была
красной и, как оказалось, ловила живой баг: в списке фокусируемых элементов не
исключались **скрытые** поля, поэтому «первым элементом формы» становилось
скрытое поле, `.focus()` по нему был no-op, и фокус оставался на кнопке
«Закрыть». Пользователь с клавиатуры лишний раз шёл до нужного поля, скринридер
читал «Закрыть» вместо «Электронная почта». Исправлено одной строкой в
`ui/dialog.tsx` + регресс-тест; проверено на живом браузере (до — кнопка,
после — поле email). Дефект был давним: e2e-тесты ручные, их просто не гоняли.

### Как перегенерировать эталоны впредь

```
npm run prisma:seed                      # partner@demo.local вымывается прогонами
npx next dev -p 3100                     # :3000 занят стендом
PLAYWRIGHT_BASE_URL=http://localhost:3100 npm run e2e:visual:update
```

Нужен **полный** Chromium (`npx playwright install chromium`), а не только
headless-shell. На сервере без root браузеру нужны библиотеки из
`~/.local/pw-libs` через `LD_LIBRARY_PATH`. Перед прогоном сбросить лимит входа
(`login:*` в Redis) — окно продлевается на каждом обращении и валит `auth.setup`.
`next dev` на полном прогоне может упасть по памяти: запускать с
`NODE_OPTIONS=--max-old-space-size=4096`.

### Историческая справка: как решение принималось

Сначала прогон делался «на разведку», и промежуточный вывод был другим:
мобильные проекты на сервере не снимались (WebKit требует прав
администратора), а Linux-снимки не коммитились — они не заменяли `*-win32.png`
и были бы мусором. Тогда ФТ-15.9 числился остатком «за владельцем».

Заказчик выбрал перевод эталонов на Linux (Windows-машины для прогона нет) —
и оба ограничения были сняты: мобильные проекты переведены на Chromium,
эталоны перегенерированы и закоммичены (38 штук), win32-снимки удалены.
Красная focus-trap-спека, которую промежуточно списали на headless-shell,
оказалась настоящим дефектом доступности и исправлена (см. выше).

Абзац оставлен, чтобы был виден ход рассуждений; **актуальное состояние —
в разделе выше**, а не здесь.
