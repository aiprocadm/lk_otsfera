Каждый инвариант закреплён тестом, названным формулировкой требования и
**падающим при развороте решения** (доказано мутационной проверкой при
внедрении: временная инверсия решения в исходнике → тест красный → откат).

Postgres (`npm run test:integration` / CI-gate).

Примечания:

- Формулировка «дедуп по СНИЛС, резерв ФИО+ДР» из постановки программы
  качества **не соответствует** ни коду, ни действующему ТЗ v0.5 — инвариант 8
  закрепляет фактическую модель. Введение СНИЛС-дедупа = новая фича (спека по
  CLAUDE.md §8 после решения заказчика).
- «Прайса» в системе нет: у `TrainingDirection` нет цены, `OrderItem.amount` —
  незаполняемый задел. Инвариант 9 закрепляет фактическую модель снимка.
- Пороги покрытия: действующий гейт (`npm run test:coverage`) держит **100%**
  по `src/lib/**`, `src/app/api/**`, `src/worker/**` и остальным логическим
  слоям — строже требуемых «≥90% на критические модули».
- Новый инвариант добавляется файлом `invariants.<slug>.test.ts` + строкой в
  этой таблице; мутационная проверка обязательна (описать в PR).
