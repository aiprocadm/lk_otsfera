# Документы и файлы

**Этап дорожной карты:** 8 «Документы и 1С — добор» · **Требования:** `У-251`…`У-254`, `У-258` · **Приоритет:** Важно · **Оценка:** 3–4 дня.
**Зависимости:** нет; `У-252` используется партнёром и заказчиком (этап 6 может ссылаться).

## 1. Цель доработки

Модуль документов закрыт двумя программами (генерация с версиями и статусами, КП, выгрузка в 1С, антивирус, presigned-скачивание с человеческим именем). Остались пробелы «файлового шкафа»: версии для **загруженных** файлов, пакетное скачивание, группировка и поиск в большой карточке, журнал «кто скачал», единый рабочий экран сотрудника с фильтром по источнику.

## 3. Что нужно изменить

**`У-251` — версии загруженных файлов.** Кнопка «Загрузить новую версию» в карточке документа с `direction = incoming/outgoing`, созданного загрузкой (не генератором): новый `Document` с `replacesDocumentId` на прежний, `version + 1`, тот же тип/направление/контрагент; прежний помечается «заменён» и скрыт из списков по умолчанию (как у генерируемых); клиентам и партнёру отдаётся только последняя версия; история версий — блок в карточке (сотрудники) с датами и авторами; аудит `document_version_uploaded`. Роуты загрузки принимают `replacesDocumentId` (аддитивно).

**`У-252` — пакетное скачивание ZIP.** В списках документов (сотрудники: экран «Документы», вкладка карточки организации, карточка заказа; заказчик: «Документы»; партнёр: «Документы» и вкладка организации портфеля) — чекбоксы и кнопка «Скачать выбранные (ZIP)»; `GET /api/documents/zip?ids=` → сервис собирает только документы в скоупе роли (чужой id молча пропускается и считается в ответе «не включено: N»), только `scanStatus = clean`, лимит 50 файлов / 500 МБ (иначе «выберите меньше» до запроса); имена внутри ZIP по правилу `У-154`; потоковая сборка `jszip` без временного файла; аудит `documents_zip_downloaded` с перечнем id.

**`У-253` — группировка и поиск.** Вкладка «Документы» карточки организации и экран «Документы» сотрудника: группировка «по типу» / «по году» / «по заказу» (переключатель, запоминается в сессии), фильтры тип · год · направление · статус · выгрузка в 1С · источник, поиск по номеру и названию файла; постраничность с `total`.

**`У-254` — журнал скачиваний.** Событие аудита `document_downloaded` (кто, когда, роль, документ, версия) пишется в download-роутах (presigned выдача = факт скачивания); в карточке документа у сотрудников — блок «Кто скачивал» (последние 20, ссылка на аудит); клиенту не показывается. Отметка просмотра клиентом (`DocumentViewMark`) остаётся для «клиент видел».

**`У-258` — единый экран «Документы» сотрудника.** Фильтр «источник»: выпущен в ЛК · из 1С · загружен клиентом · загружен партнёром · загружен сотрудником · из Битрикса (после этапа 2); массовые действия: «Выгрузить в 1С» (есть), «Скачать ZIP» (`У-252`), «Отправить клиенту» (для выпущенных, через `У-149`, по одному письму на организацию). Источник вычисляется из `generationSource`, `externalId`, `direction`, `uploadedByRole` (новое поле, бэкфилл по аудиту где возможно, иначе «не определён»).

## 5. Сущности данных

`Document.uploadedByRole String?` (аддитивно); остальное — существующие поля.

## 6. API / actions

`GET /api/documents/zip` (все роли по скоупу); загрузка — существующие роуты с `replacesDocumentId`; server action `sendDocumentsToClientAction` (массовая отправка).

## 7. Роли

Версии загружает роль, которая загрузила исходный файл, и сотрудники ЦО; ZIP — все роли в своём скоупе; журнал скачиваний и «источник» — только сотрудники.

## 8. Что скрыто

Клиент и партнёр не видят: старые версии, «кто скачивал», источник, статус выгрузки в 1С, чужие документы в ZIP (молча пропускаются — без раскрытия существования).

## 9. Ошибки и edge cases

- Новая версия на документ, уже выгруженный в 1С → пометка «в 1С ушла версия N» и кнопка «Выгрузить повторно» (механизм `У-169`).
- ZIP с одним файлом — всё равно ZIP (предсказуемость).
- Файл `pending` антивирусом — в ZIP не попадает, в ответе «ожидает проверки: N».
- Дубль имени внутри ZIP — суффикс `(2)`.

## 10. Критерии приемки

- [ ] Новая версия загруженного файла скрывает старую у клиента и показывает историю сотруднику; аудит пишется.
- [ ] ZIP собирается только из документов скоупа роли и `clean`; лимиты соблюдены; имена человеческие; чужой id не раскрывается.
- [ ] Группировка и фильтры работают на карточке организации и экране «Документы»; `total` есть.
- [ ] «Кто скачивал» показывает скачивания клиента и сотрудника; клиент блока не видит.
- [ ] Фильтр «источник» различает шесть источников; массовая отправка клиенту создаёт по одному письму на организацию.
- [ ] Стражи: IDOR ZIP (партнёр не получает документ чужой организации), 410 для инфицированных, мутационная проверка.
