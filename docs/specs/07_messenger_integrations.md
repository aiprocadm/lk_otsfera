# Интеграции с мессенджерами и коммуникационный центр

**Этап дорожной карты:** 3 «Коммуникационный центр v2» · **Требования:** `У-204`…`У-217` · **Приоритет:** MVP, кроме `У-212` (Важно) · **Оценка:** 6–8 дней.
**Зависимости:** этап 1 (контакты — карточка и «Написать»); спека мессенджеров 12.09 (`Р-М-1`…`Р-М-10`) — база, ничего из неё не переписывается.

## 1. Цель

Довести диалоги мессенджеров (отгружены 12.09.2026, PR #580…#583) до **коммуникационного центра CRM**: ответить на письмо, приложить файл, назначить ответственного, ответить шаблоном, принять заявку с сайта, видеть переписку в карточке организации и контакта, а клиенту — писать из кабинета. Всё это — на существующих сущностях `MessengerDialog`/`MessengerMessage`/`InboundMessage`/`Contact`.

**Что найдено в коде.** `services/messengers/` (`dialog.ts`, `list.ts`, `get.ts`, `send.ts`, `bind.ts`, `scope.ts`, `channels.ts`, `transport.ts`, `appendInbound.ts`, `recordOutbound.ts`, `availability.ts`, `backfill.ts`); экраны `/manager/messengers`, `/manager/messengers/[id]`; `/admin/settings/integrations/messengers`; вебхуки `api/integrations/{telegram,max,whatsapp}/webhook`; `MessengerDialog` без `assigneeId`, `status String @default("open")`, `MessengerMessage` без полей вложения (`schema.prisma:2347-2410`); `inbound/sendReply.ts:65` — `email_unsupported`; `InboundMessage.attachmentPath/attachmentMime/scanStatus` — вложения живут только в инбоксе; `ClientRequestSource.website` без пути создания; уведомление `messenger_message` (аудитория `staff`); флаг `inbound_messaging` — поведенческий (`Р-М-4`).

## 3. Единый inbox

Не меняется по структуре (`Р-М-1`): **«Входящие в работу»** (Intake) — очередь непривязанного и неразобранного (письма, звонки, диалоги без компании, вопросы из кабинета, обращения с сайта); **«Мессенджеры»** — переписка. `У-215`: строка инбокса, порождённая сообщением из мессенджера/почты, показывает ссылку «Открыть диалог» и наоборот; бейджи меню (`services/intake/badges.ts`, `staff/badges`) считают диалоги в статусе `waiting_staff` (после `У-207`) и непривязанные.

## 4. Привязка диалогов к CRM

Есть: организация (`bind.ts`), контакт (`contactId`), пользователь кабинета (`userId`), компания по «первому ответившему» (`Р-М-2`). Добавляется:
- `У-210`: вкладка **«Диалоги»** в карточке организации (реестр `orgCardTabs`, ЦО), вкладка «Диалоги» в карточке контакта (`У-179`), блок «Переписка с клиентом» в карточке заказа по `Order.primaryContactId` и организации (ссылки на диалоги; создать диалог с контактом заказа).
- Привязка к сделке/лиду: **не заводим** отдельных полей — диалог принадлежит контакту/организации, сделка видит диалоги через контакт (`Deal.contactId`). Кнопка «Создать лид из диалога» (есть в Intake) переносит `contactId`.

## 5. Карточка диалога

`/manager/messengers/[id]` — дополняется: шапка с контактом/организацией/каналом/ответственным/статусом; лента сообщений с вложениями и внутренними заметками (визуально отличаются); форма ответа с кнопками «Шаблон», «Прикрепить», «Заметка»; правая панель: контакт (каналы), организация (заказы в работе, задолженность — только сотруднику), задачи по диалогу (`У-220`), «Создать лид / Задачу».

## 6. История переписки

Без изменений (все сообщения в обе стороны, `У-Р-М-10` бэкфилл). `У-205` расширяет бэкфилл на письма: `InboundMessage` канала `email` сворачиваются в диалоги по нормализованному адресу отправителя; исходящие письма-ответы записываются как `MessengerMessage(direction: 'outbound', channel: email)`.

## 7. Внутренние комментарии

`У-209`: сообщение с `direction = 'note'` — не отправляется, видно только сотрудникам компании; в клиентскую переписку (`У-234`) не отдаётся; поиск по тексту заметок в фильтре диалогов; упоминание `@коллега` → уведомление `note_mention` (общее с `У-183`).

## 8. Ответственные

`У-206`: `MessengerDialog.assigneeId String?` (+ `assignedAt`, `assignedById`); кнопки «Взять себе» и «Назначить» (выбор из сотрудников компании); фильтры списка «мои · без ответственного · все»; автоназначение: ответивший на диалог без ответственного становится ответственным (правило первого ответившего, как для компании); уведомление `messenger_message` уходит ответственному, а при его отсутствии — менеджерам организации (как сейчас); смена ответственного — аудит и уведомление новому.

`У-207` статусы: `open` (новый) → `waiting_staff` (входящее без ответа) → `waiting_client` (ответили) → `closed` (закрыл сотрудник; новое входящее открывает снова). Автопереходы в `appendInbound.ts`/`send.ts`; ручное закрытие с кнопкой. SLA: диалог в `waiting_staff` дольше `Company.slaResponseHours` подсвечивается и попадает в `monitoring.slaEscalation` руководителю (расширение процессора; событие `sla_escalation` уже есть); порог «предупреждение» — `slaWarningHours`.

## 9. Шаблоны сообщений

`У-208`: модель `ReplyTemplate` (`companyId`, `title`, `body`, `channels: String[]` пусто = все, `isActive`, `sortOrder`, `updatedById`); раздел хаба «Конфигурация процессов → Шаблоны ответов» (`/{admin,leader}/settings/processes/reply-templates`); подстановки `{{contact.name}}`, `{{organization.name}}`, `{{manager.name}}`, `{{manager.phone}}`, `{{order.number}}` (если диалог привязан к заказу через контакт — берётся последний заказ в работе, иначе подстановка пустая с предупреждением до отправки); неизвестная подстановка — ошибка сохранения (как `У-128`); в форме ответа — кнопка «Шаблон» с поиском, вставка с предпросмотром, правка перед отправкой; счётчик использований в аудите (для очистки неиспользуемых).

## 10. Вложения

`У-204`:
- **Входящие:** вебхуки Telegram (`getFile` → скачать по `file_path`), MAX (по ссылке медиа), WhatsApp (если агрегатор отдаёт URL) → `upload-core` в S3 (`messengers/<dialogId>/<uuid>`), запись `MessengerMessage.attachmentPath/attachmentName/attachmentMime/attachmentSize/scanStatus`, очередь `docs.scanDocument`; до `clean` показывается «проверяется», `infected` → «файл заблокирован» (410 при скачивании, как в download-роутах).
- **Исходящие:** кнопка «Прикрепить» (API-роут `POST /api/manager/messengers/[id]/attachment` на `useFetchSubmit`, лимит `DOCUMENT_MAX_FILE_SIZE_MB` и лимит канала: Telegram 50 МБ, MAX/WhatsApp — по документации провайдера, показывается в подсказке из `DEFAULT_MAX_FILE_SIZE_MB`); отправка `sendDocument`/`sendPhoto` через `transport.ts` (расширение `sendToMessenger` типом `attachment`); e-mail — вложение письма.
- **Скачивание:** `GET /api/manager/messengers/[id]/attachment/[messageId]` → presigned URL 302; клиентская переписка (`У-234`) — свои вложения тем же механизмом.
- Один файл на сообщение (упрощение; несколько — несколько сообщений).

## 11. Уведомления

`messenger_message` (есть) — таргетинг по ответственному (`У-206`); `sla_escalation` — диалоги (`У-207`); `note_mention` — заметки (`У-209`); `client_request_submitted` — с сайта (`У-211`, аудитория staff, с пометкой «с сайта»); клиенту при ответе сотрудника: в бот (есть) и в кабинет/почту (`У-212`, `У-234`).

## 12. Настройки подключения

Раздел «Подключение мессенджеров» (есть, `Р-М-6`) дополняется:
- `У-213`: светофор по каналу (последний принятый вебхук, последняя ошибка отправки с текстом, размер очереди повторов), кнопка «Отправить тестовое сообщение себе» (в привязанный бот администратора), «Проверить вебхук» (Telegram `getWebhookInfo`, MAX — аналог).
- `У-211`: раздел **«Сайт»** (`/admin/settings/integrations/website`): токен формы (генерируется, показывается один раз, хранится `isSecret`), разрешённый домен (Origin) сайта, включение/выключение, сниппет HTML-формы для WordPress (otsfera.ru) с полями: имя, телефон, e-mail, организация, сообщение, согласие на обработку ПДн, honeypot.
- Все секреты — только администратору (`Р-22`); руководитель видит светофор.

## 13. Логи и ошибки

`У-213`: `MessengerMessage.deliveryStatus` (`sent | failed | pending`) + `deliveryError` (текст провайдера, без секретов); в диалоге сообщение с `failed` помечено и имеет кнопку «Повторить» (переотправка через транспорт, аудит); повтор из воркера не делаем (человек решает); ошибки вебхуков — `log.warn` со `scrub()` и счётчик в светофоре; таблица `SyncLog` не используется (она про 1С) — свой лёгкий счётчик на `IntegrationSetting` не заводим, берём агрегаты из `MessengerMessage`/`AlertState`.

## 14. Безопасность

- Скоуп диалогов: компания + очередь непривязанных (`Р-М-3`) **плюс** `У-214`: capability `communications.dialogs` со `ScopeLevel` (`own` — только где ответственный или организация в `managedOrgIds`; `assigned`/`all` — как сейчас), `teamMode` уважается; страж «сотрудник с `own` не видит чужой диалог».
- Вложения: MIME allow-list, размер, антивирус, presigned 600 с; заметки не утекают клиенту (тест).
- Публичный роут (`У-211`): токен в заголовке `X-Site-Token`, `Origin` в списке, rate-limit по IP (`lib/rateLimit`, 10/мин), honeypot-поле → молчаливый 200 без записи, Zod-форма, размер тела ≤ 16 КБ, без вложений; ПДн формы — обращение (`ClientRequest`), не логируются.
- Один бот на платформу: диалог не может принадлежать двум компаниям (`Р-М-2`) — зафиксировано как ограничение; бот на компанию — вне программы.
- Email-ответ: только с адреса компании (`IntegrationSetting` `email.from`), `Reply-To` на входящий ящик IMAP, чтобы ответ клиента вернулся в тот же диалог.

## 16. Критерии приемки

- [ ] Фото из Telegram появляется в диалоге после антивируса; менеджер отправляет PDF клиенту в бот; заражённый файл заблокирован (410).
- [ ] На входящее письмо менеджер отвечает из инбокса/диалога; ответ клиента приходит в тот же диалог (`In-Reply-To`/адрес); `email_unsupported` нигде не возвращается.
- [ ] Ответственный назначается, автоназначается первым ответившим, фильтр «мои» работает; уведомление о новом сообщении получает ответственный.
- [ ] Статусы переключаются автоматически; диалог старше SLA подсвечен и виден руководителю в эскалации.
- [ ] Шаблон с подстановками вставляется и правится; неизвестная подстановка не сохраняется; руководитель правит шаблоны только своей компании.
- [ ] Заметка в диалоге не уходит клиенту ни в бот, ни в кабинет (тест).
- [ ] Форма с сайта создаёт обращение с `source = website`, оно во «Входящих в работу»; без токена — 401, чужой Origin — 403, 11-й запрос в минуту — 429, honeypot — 200 без записи.
- [ ] Вкладка «Диалоги» есть в карточке организации и контакта (ЦО), отсутствует у партнёра/заказчика (исключение записано).
- [ ] Светофор показывает ошибку доставки; «Повторить» переотправляет; тестовое сообщение приходит администратору.
- [ ] `У-214`: профиль `own` не видит чужой диалог (страж-мутация); `У-217`: все стражи проверены мутацией, покрытие 100 %.
- [ ] (`У-212`) Сообщение из кабинета заказчика попадает менеджеру в диалог канала `cabinet`; ответ — в кабинет и в бот; глоссарий обновлён.
