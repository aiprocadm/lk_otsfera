# Партнерский кабинет

**Этап дорожной карты:** 6 · **Требования:** `У-237` (материалы), `У-238`, `У-239`, `У-240`, `У-241` (общие с заказчиком), `У-228` (уведомления), `У-234` (переписка, Важно) · **Приоритет:** MVP (`У-237`, `У-238`, `У-240`), Важно (`У-234`, `У-239`) · **Оценка:** 2–3 дня сверх работ кабинета заказчика.

## 1. Цель

Кабинет партнёра уже зеркален кабинету заказчика (`У-115`, `У-121`): портфель организаций с карточками, заказы (`/partner/orders`, `У-109`), обращения, заявки, удостоверения, документы (в том числе выпущенные сотрудниками, `У-155`), финансы с комиссионными отчётами PDF/XLSX и корректировками, команда, настройки. Не хватает одного собственного раздела — **«Материалы»** — и общих с заказчиком доборов.

**Что найдено в коде.** `src/app/partner/*` — 21 страница; `services/partner/` (`portfolio.ts`, `orders.ts`, `finance.ts`, `team.ts`, `requisites.ts`, `orgDocuments.ts`, `dashboard.ts`); суб-роли `partnerRole` `admin`/`manager` + `assignedOrgIds`; `partner_leads` — легаси-флаг (правило v0.5: партнёр подаёт только обращения). Материалов для партнёров нет (`grep -rniE "материал.*партн" src` → 0).

## 2. Главные сценарии партнера

1. Привести организацию → подать обращение/заявку → следить за статусом и ответом (`У-238`).
2. Видеть по каждой организации портфеля заказы, документы, удостоверения (есть).
3. Скачать актуальный прайс, презентацию, шаблон письма клиенту (`У-237`).
4. Проверить начисление комиссии и получить отчёт (есть).
5. Написать менеджеру и получить ответ в кабинете (`У-234`).
6. Добавить сотрудника партнёра и назначить ему организации (есть).

## 3. Дашборд партнера

- «Ваш менеджер» (`У-240`) — менеджер партнёра: `Partner` получает `managerId` (ответственный за партнёра; правит админ/руководитель в карточке партнёра `/admin/partners/[id]`); если не назначен — менеджер первой организации портфеля; кнопка «Написать».
- «Первые шаги» (`У-239`) для нового пользователя партнёра: реквизиты партнёра → первая организация в портфеле → бот привязан → команда приглашена (у `admin`).
- Плитки: организаций в портфеле, заказов в работе, начислено за месяц, обращений без ответа — как сейчас (спека этапа сверяет).

## 4. Клиенты партнера

«Портфель» без изменений. В карточке организации у партнёра **нет** вкладок «Контакты», «Заметки», «Диалоги» (исключение зеркала: внутренние данные продавца).

## 5. Заявки партнера

Обращения — ответ сотрудника виден (`У-238`, общий механизм). Заявки на обучение — без изменений.

## 6. Статусы и воронка

Партнёр видит статусы обращений (`submitted → in_triage → converted/rejected`) и заказов (`OrderStatusDefinition`, публичные названия). Внутренней воронки (лиды/сделки) партнёр не видит — правило не меняется. Статус «converted» получает пояснение «принято в работу, создан заказ №…», если заказ есть и относится к его портфелю.

## 7. Документы

Без изменений (загрузка по заказу и без заказа, просмотр выпущенных, скачивание). Из этапа 8 — ZIP (`У-252`).

## 8. Вознаграждения / комиссии

Без изменений: ставка только на чтение (`У-1`…`У-4`), отчёты, корректировки, `see_commission` не применяется к партнёру (видит только свою комиссию).

## 9. Коммуникации

`У-234`: «Сообщения» → «Переписка с менеджером» (диалоги пользователя партнёра, канал `cabinet` + мессенджеры) и «По заказам». Уведомления о новом сообщении — в кабинет и в привязанный бот.

## 10. Материалы для партнеров

`У-237`:
- **Модель** `PartnerMaterial` (`companyId`, `title`, `description?`, `documentId` → `Document` в S3 (загрузка через `upload-core`, антивирус), `category` enum `price_list | presentation | template | instruction | other`, `publishedAt?`, `isActive`, `sortOrder`, `updatedById`).
- **Публикация** — хаб «Конфигурация процессов → Материалы для партнёров» (`/{admin,leader}/settings/processes/partner-materials`): список, загрузка файла (API-роут, не server action — CLAUDE.md §11), правка описания, снятие с публикации, история версий через `replacesDocumentId` (при замене файла старая версия скрывается).
- **Раздел партнёра** `/partner/materials` (пункт меню между «Портфель» и «Сообщения»): карточки по категориям, поиск, кнопка «Скачать» (presigned URL), дата обновления, метка «Новое» 7 дней. Видит партнёр материалы компаний, у которых есть хотя бы одна его организация; пустое состояние — «Материалов пока нет».
- **Уведомление** `partner_material_published` (аудитория партнёр, каналы по правилам компании) при публикации.
- **Доступ:** только чтение и скачивание; скачивание пишет аудит `partner_material_downloaded` (кто, что) — руководитель видит «кто скачал» в хабе.

## 11. Пользователи партнера

Без изменений (`admin`/`manager`, `assignedOrgIds`, лимит 5). Добор: у `manager` без назначенных организаций — пустое состояние портфеля с подсказкой (проверяется в приёмке этапа).

## 12. Что партнер не должен видеть

Оплаты и задолженность клиента; лиды, сделки, воронку; задачи, заметки, контакты как справочник; данные организаций вне портфеля; ставки других партнёров; внутренние заметки в диалогах; материалы компаний, с которыми нет организаций в портфеле.

## 13. Критерии приемки

- [ ] `/partner/materials` показывает опубликованные материалы по категориям; скачивание работает; аудит пишется; исключение зеркала записано.
- [ ] Публикация из хаба у admin и leader (своя компания); снятый с публикации материал у партнёра исчезает; замена файла скрывает старую версию.
- [ ] Уведомление о новом материале приходит по правилам компании.
- [ ] «Ваш менеджер» показывает менеджера партнёра или менеджера первой организации.
- [ ] Ответ сотрудника на обращение виден в карточке обращения партнёра.
- [ ] `manager` партнёра не видит материалы чужой компании и организации вне `assignedOrgIds` (тест IDOR).
- [ ] Экраны проходят три вопроса и 390×844; мобильная панель партнёра не короче четырёх вкладок (`У-117`).

## 14. Риски и edge cases

- Партнёр с организациями у двух компаний-продавцов видит материалы обеих — с подписью компании-издателя.
- Материал без файла (только описание) — недопустим: файл обязателен; ссылка на внешний ресурс — поле `externalUrl?` вместо файла (либо файл, либо ссылка; проверка формы).
- Инфицированный файл материала (`scanStatus = infected`) не публикуется: публикация ждёт `clean`; в хабе — статус «проверяется антивирусом».
