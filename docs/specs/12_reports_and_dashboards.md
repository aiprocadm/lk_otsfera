# Отчёты и дашборды

**Этап дорожной карты:** 7 «Отчёты и KPI» · **Требования:** `У-242`…`У-250` · **Приоритет:** MVP · **Оценка:** 5–6 дней.
**Зависимости:** этап 3 (метрики коммуникаций), этап 4 (просроченные задачи); `leader_analytics` включён.

## 1. Цель доработки

Руководитель ведёт ~6 KPI в Excel; в системе есть план/факт только по выручке (`SalesTarget`) и три счётчика у менеджера. Нужны: **конфигуратор KPI** с планом по менеджерам, **аналитика** по пяти разрезам, **реестр стандартных отчётов с экспортом XLSX**, KPI на дашбордах менеджера и администратора.

## 3. Что нужно изменить

**`У-242` — конфигуратор KPI.** `SalesTarget` обобщается колонкой `metric String @default('revenue')` (миграция аддитивна, уникальность `(companyId, managerId, period, metric)`; `Р-Б-7`). Реестр метрик в коде `src/lib/kpi/metrics.ts` — каждая: ключ, русское название, единица, функция расчёта факта по компании/менеджеру/периоду (SQL `groupBy`), описание словами. Метрики MVP: `revenue_paid` (оплачено, ₽), `orders_created`, `leads_created`, `proposals_sent`, `deals_won`, `calls_outbound`, `dialogs_answered`, `avg_first_response_min`, `tasks_overdue`, `certificates_issued`. Раздел хаба «Конфигурация процессов → KPI» (`/{admin,leader}/settings/processes/kpi`): выбор активных метрик компании (до 8 на дашборд), планы по менеджерам на месяц (таблица «менеджер × метрика», копирование с прошлого месяца), единицы и порядок. Заказчик сопоставляет свои шесть Excel-показателей с реестром на спеке этапа; отсутствующий показатель — новая метрика в реестре (не пользовательская формула).

**`У-243` — «Аналитика» руководителя** — вкладки: **План/факт** (все активные KPI, по менеджерам и команде, % выполнения, тренд к прошлому месяцу); **Воронка** (есть, + по источникам `У-247`); **Коммуникации** (время первого ответа по каналам/менеджерам, доля диалогов с просрочкой SLA, входящие без ответа, звонки принятые/пропущенные); **Дебиторка** (задолженность по организациям: сумма, срок с даты счёта, ответственный, ссылка; итог по компании; фильтр «старше N дней»); **Партнёры** (начислено/выплачено, активные организации, обращения по партнёрам). Admin — те же вкладки в `/admin/finance` с выбором компании.

**`У-244` — реестр отчётов с экспортом.** `src/lib/reports/registry.ts`: каждый отчёт — ключ, название, роли, параметры (период, менеджер, организация), колонки, функция выборки (скоуп внутри), `GET /api/reports/[key]/export?…` → XLSX (`exceljs`), не более 50 000 строк (иначе «сузьте период»). Отчёты MVP: `plan_fact` (план/факт), `funnel_by_source` (воронка по источникам), `receivables` (дебиторка), `communications` (SLA и ответы), `partner_accruals` (начисления партнёров), `manager_load` (загрузка: заказы/задачи/диалоги на менеджера). Вкладка «Экспорт» в «Аналитике» и кнопка «XLSX» на каждой вкладке.

**`У-245` — дашборд менеджера.** KPI-сетка расширяется строкой «Мои KPI за месяц»: активные метрики компании с планом/фактом менеджера (только свои — `У-249`); клик ведёт в соответствующий раздел (например, «КП отправлено» → документы-КП за период).

**`У-246` — дашборд администратора.** Кросс-компанийные плитки: заказы/оплаты/лиды/обращения за месяц по компаниям, документы не выгружены в 1С (`У-174`), очереди и DLQ (есть), последний пакет миграции (`У-198`).

**`У-247` — источники.** Отчёт и вкладка: лиды и обращения по источникам (`LeadSource`, `ClientRequestSource` + `website`, `inbound_message`, `call`, `partner_cabinet`, `organization_cabinet`, `manual`, `bitrix` после этапа 2) → сделки → заказы; конверсия по каждому.

**`У-248` — производительность.** Агрегаты через `groupBy`/сырой SQL с индексами по (`companyId`, дата) там, где их нет (спека этапа перечисляет по `EXPLAIN`); отчёт за месяц по 100 000 заказов — < 2 с; тест-страж на отсутствие `findMany` в циклах в `src/lib/reports/**` и `src/lib/kpi/**` (образец `С-8`).

**`У-249` — права.** Руководитель — своя компания; менеджер — только свои KPI (страница `/manager/dashboard`, API экспорта ему недоступен — 403); партнёр — только `partner_accruals` по себе (через `/partner/finance`, есть); `see_commission` соблюдается в `partner_accruals` для менеджера.

**`У-250` — стражи.** Реестр отчётов ↔ страница «Экспорт» (каждый ключ имеет название и роли; тест колонок и скоупа на каждый отчёт); реестр метрик ↔ хаб KPI; мутационная проверка; покрытие 100 %.

## 8. Что должно быть скрыто

Менеджер не видит KPI коллег и комиссию без `see_commission`; клиенты и партнёры — ничего из аналитики, кроме своих финансов.

## 9. Ошибки и edge cases

- Период без данных — нули, не ошибка; метрика без плана — «план не задан».
- Менеджер уволен (`isActive = false`) — остаётся в отчётах за прошлые периоды с пометкой.
- Часовой пояс — сутки по Москве (хотфиксы №20/№21): границы периодов через `src/lib/dates`.
- Экспорт > 50 000 строк — отказ до выборки с подсказкой.

## 10. Критерии приемки

- [ ] Руководитель включает шесть метрик, задаёт планы по менеджерам, копирует с прошлого месяца; «Аналитика → План/факт» показывает выполнение по каждому.
- [ ] Вкладки «Коммуникации», «Дебиторка», «Партнёры» показывают данные фикстуры; экспорт XLSX совпадает с экраном (тест на колонки).
- [ ] Менеджер видит свои KPI на дашборде и получает 403 на экспорт руководителя.
- [ ] Отчёт по источникам различает сайт, партнёра, кабинет, звонок, мессенджер.
- [ ] Отчёт за месяц на фикстуре 100 000 заказов — < 2 с (интеграционный тест с тайм-лимитом); страж N+1 зелёный.
- [ ] Admin видит кросс-компанийные плитки; три вопроса и 390×844; глоссарий: «KPI», «План/факт», «Дебиторка».
