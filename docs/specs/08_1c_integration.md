# Интеграция с 1С

**Этап дорожной карты:** 8 «Документы и 1С — добор» · **Требования:** `У-255` (Позже), `У-256`, `У-257` (Важно) · **Оценка:** 3–4 дня (без `У-255`).
**Зависимости:** этап 1 (контакты) для `У-256`; согласование методов контракта со стороной 1С для `У-255`, `У-257`.

## 1. Цель

Обмен с 1С — самый проработанный модуль проекта (две программы ТЗ, ADR-0003/0004, контракт `docs/integrations/1c-contract.md`). Цель этапа — **не переделывать**, а закрыть три пробела, которые видны на фоне CRM: контакты контрагентов из 1С, сверка дебиторки и (позже) номенклатура ↔ каталог. Остальное в этом файле — **описание того, что уже есть**, чтобы Claude Code не спроектировал второй обмен.

**Что найдено в коде.** `src/lib/services/oneCSync/` (адаптеры `adapter-rest.ts`/`adapter-file.ts`, `push.ts`, `writers.ts`, `mappers.ts`, `schemas.ts`, `sync-reconcile.ts`, `config.ts`), очереди `oneCSync.{pullOrders,pullPayments,pullDocuments,pullOrganizations,pushLead,pushDocument,reconcile}`, mock-сервер `mock-1c/`, импорт Excel `services/import/` (`OneCImportBatch`, предпросмотр, откат `rollback.ts`, история `history.ts`), выписка 51 `services/import/oneCAccountCard/` (`PaymentImportBatch`, организации без ИНН — `У-83`…`У-93`), UI: `/admin/settings/integrations/1c/{excel,payments,auto,history,documents}` и у руководителя (своя компания), у менеджера — «Обмен с 1С» с вкладками. Параметры и расписания — из UI (`У-125`), правило выгрузки документов — на `Company` (`У-169`).

## 2. Сущности для синхронизации

| Сущность промпта | В проекте | Статус |
|---|---|---|
| Контрагенты / компании | `Organization` (ИНН, реквизиты, `legalName`, банковские) | есть (`GET Organizations`, `У-171`) |
| Контакты | `Contact` | **`У-256`** |
| Договоры | `Document` типа `contract` (из ЛК → 1С; из 1С → ЛК как файл документа) | есть |
| Счета | `Document` типа `invoice` (ЛК → 1С; оплата — по платежам 1С) | есть |
| Акты | `Document` типа `act` (обе стороны) | есть |
| Заказы / реализации | `Order` (1С — источник истины, ADR-0004) | есть |
| Оплаты | `Payment` (REST `GET Payments` и выписка 51) | есть |
| Номенклатура / услуги | `CatalogItem.code` заполняется вручную | **`У-255`** (Позже) |
| Статусы документов | `Document.status`, `signedAt` из 1С (`У-170`) | есть |
| Задолженности | вычисляется `totalAmount − paidAmount`; сверки с 1С нет | **`У-257`** |
| Реквизиты | `Organization.*` из 1С, «пустое не затирает» | есть |
| Документы закрытия, файлы | `GET Documents` (файлы по сделкам), антивирус | есть |

## 3. Направления обмена

- **1С → ЛК (pull):** контрагенты, реализации, оплаты, документы; расписания по каждой задаче из UI; курсор `SyncState` с overlap; `shadow/live` режим.
- **ЛК → 1С (push):** лиды (`pushLead`), документы ЛК (`pushDocument`, авто/по кнопке/никогда на уровне компании; КП не выгружается — `Р-14`); файловый пакет для бухгалтера (Excel + ZIP, `У-173`).
- **Сверка:** `reconcile` — документы `pushed` проверяются по `externalId`, зависшие лиды переотправляются (`У-172`).
- **Ручной ввод:** Excel-выгрузка 1С (организации, заказы) и карточка счёта 51 (оплаты + автосоздание организаций).

## 5. Контрагенты

Есть. Изменений нет. Напоминание для агента: `Company` ≠ `Organization`; писатель, минтящий `Company` при импорте, — дефект (`Т-41`…`Т-44` прежнего ТЗ).

## 6. Договоры

Есть как документы. Отдельной сущности «Договор» не заводим; связи «акт → счёт», «ДС → договор» — `parentDocumentId` (`У-151`).

## 7. Счета

Есть. Признак оплаты счёта — по платежам заказа с привязкой «платёж → счёт» по номеру из назначения платежа (`У-148`). Клиент видит в «Финансы → Счета» (`У-235`).

## 8. Акты

Есть в обе стороны.

## 9. Заказы

Есть. Заказы из миграции Битрикса (`У-197`) получают `externalId = bitrix:deal:<id>` и **не** обновляются 1С-синком (ключи не пересекаются); при появлении того же заказа из 1С — ручное объединение через карточку заказа (кнопка «Это тот же заказ, что …» — часть `У-197`).

## 10. Оплаты

Есть (REST + выписка 51 с созданием организаций без ИНН).

## 11. Номенклатура / услуги

`У-255` (**Позже**, требует стороны 1С): метод контракта `GET /api/nomenclature` (код, название, единица, ставка НДС); экран «Каталог услуг и цены → Сопоставление с 1С»: таблица `CatalogItem` × номенклатура, автоподбор по названию, ручной выбор, сохранение `code`; выгрузка документов (`У-167`) передаёт код номенклатуры в строках, когда он есть. Цены остаются в ЛК (Р-13).

## 12. Логи синхронизации

Есть: `SyncLog`, вкладка «История» (все каналы, включая «Документы → 1С»), светофор интеграции (`У-70`, `У-174`), ops-алерты с порогами из UI (`У-126`), DLQ с повтором (`/api/admin/dlq`).

## 13. Ручной повтор

Есть: «Выгрузить повторно» на документе, массовая выгрузка, ручной запуск задач синка, повтор DLQ. Добавляется: повтор сверки дебиторки по кнопке (`У-257`).

## 14. Ошибки и конфликты

Есть коды и русские строки (`errors/messages.ts`). Новые коды этапа: `debt_mismatch`, `nomenclature_not_found`, `contact_conflict`.

`У-256` — контакты контрагента из 1С: `OneCOrgSchema` расширяется полем `contacts: [{ name, position?, phone?, email? }]` (аддитивно, необязательно); `mappers.ts`/`writers.ts` создают/обновляют `Contact` организации по нормализованному телефону/e-mail (`resolveContactByChannel.ts`); правило «пустое не затирает»; конфликт канала с контактом другой организации → не пишем, строка в `SyncLog` уровня `warn` с ссылкой на объединение; контракт и `mock-1c` фикстуры обновляются; клиенту контакты не видны.

`У-257` — сверка дебиторки: метод `GET /api/debts?since=` (контрагент ИНН, заказ `externalId`, сумма долга на дату) в контракте; задача `oneCSync.reconcileDebts` раз в сутки (расписание из UI по механизму `У-125`); сравнение с `totalAmount − paidAmount` по заказам; расхождение > 1 руб. → строка отчёта «Расхождения по дебиторке» (вкладка «История» → канал «Дебиторка», экспорт XLSX) и алерт по порогу (`У-126`); ЛК данные не правит — только показывает; кнопка «Повторить сверку».

## 15. Безопасность

Без изменений: ключ 1С и режим — только admin; руководитель — своя компания на чтение; IP/подпись как в контракте; клиенту не отдаются технические поля (`externalId`, статус выгрузки).

## 16. API

Контракт `docs/integrations/1c-contract.md` дополняется §8 `GET Debts` и §9 `GET Nomenclature` (с пометкой «ожидает реализации на стороне 1С»); `OneCOrgSchema.contacts` — в §1. Страж «контракт описывает все поля, которые принимает код» (хотфикс №42) обновляется тем же PR.

## 17. Критерии приемки

- [ ] `У-256`: контакты из фикстуры `mock-1c` появляются у организации после `pullOrganizations`; повторный запуск не дублирует; пустой телефон в 1С не стирает телефон в ЛК; конфликт канала — предупреждение в истории, не падение.
- [ ] `У-257`: сверка находит искусственное расхождение в фикстуре, показывает его в истории и в отчёте XLSX; алерт срабатывает по порогу; кнопка повтора работает; данные заказов не изменены.
- [ ] `У-255` (когда наступит): сопоставление сохраняет `code`, выгрузка документов передаёт код; без ответа 1С экран показывает «метод не подключён» вместо ошибки.
- [ ] Контракт и матрица методов синхронизированы с кодом (страж хотфикса №42); `docs/integrations/1c-meeting-agenda.md` дополнен двумя вопросами к разработчику 1С.
