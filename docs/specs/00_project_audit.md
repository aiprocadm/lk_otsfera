## 1. Краткое резюме

1. **Проект технически зрелый, а не «прототип с заглушками».** 88 моделей Prisma, 108 миграций, 186 страниц в шести кабинетах, 95 API-роутов, 1 318 файлов тестов, 79 тестов-стражей, порог покрытия 100 % по логическим слоям, CI, режим сопровождения с 26 прогонами и 47 хотфиксами за неделю. В боевом коде **0** `TODO`/`FIXME`/`HACK` и **0** заглушек вида `not implemented`/`stub` (`grep -rnE "TODO|FIXME|HACK" src` без тестов → 0 совпадений).
2. **Прежние программы ТЗ отгружены целиком.** ТЗ 21.08.2026 (99 требований `У-78`…`У-176`, 10 этапов) закрыто 05.09.2026 (81 PR, `docs/tz/2026-09-05-tz-cabinets-program-DONE.md`). Мессенджеры как канал переписки — отгружены 12.09.2026 четырьмя PR (#580…#583). Поэтому раздел «что не сделано» в этом аудите — про **продуктовые** пробелы, а не про недописанный код.
3. **Главный пробел под цель «заменить Битрикс24» — сама миграция из Битрикс24: кода нет вовсе** (`grep -rli bitrix src` → 0 файлов; упоминания только в трёх исторических спеках). Без переноса компаний, контактов, лидов, сделок, задач и файлов отдел продаж не сможет выключить Битрикс.
4. **Второй пробел — CRM-сущность «Контакт» без экрана.** Модель `Contact`/`ContactChannel` есть, флаг `contacts` выключен «до появления `/manager/contacts`» ([docs/feature-flags-matrix.md](../feature-flags-matrix.md), строка `contacts`). Внутренних заметок по организации нет (есть `DealNote` по сделкам и клиентский `Comment` по заказу).
5. **Коммуникационный центр — версия 1.** Диалоги мессенджеров текстовые, без вложений, без ответственного, без шаблонов ответов; на входящее **письмо** ответить из CRM нельзя (`src/lib/services/inbound/sendReply.ts:65` → `email_unsupported`); формы с сайта нет (`ClientRequestSource.website` объявлен, пути создания нет).
6. **Автоматизация, KPI-конфигуратор, центр уведомлений, материалы для партнёров — не найдены.** Это те функции Битрикс24, которыми пользуется отдел продаж, и которые нужны в замене.
7. **Лишнее найдено, но немного и конкретно:** четыре закоммиченных лог-файла, две мёртвые таблицы (`SavedView`, `Upload`), устаревшая RBAC-матрица в README, ~16 флагов раскатки, которые давно включены навсегда, легаси-адреса-шлюзы.

## 12. Рекомендации

1. **Сначала контакты и заметки, потом миграция** (`Р-Б-4`): импорту из Битрикса нужно, куда положить контакты и комментарии, иначе они потеряются.
2. **Миграция — как импорт 1С**: предпросмотр → применение → откат → отчёт сверки; тот же UX, те же стражи (`У-193`, `У-196`, `У-198`).
3. **Кабинет — это тоже канал** (`Р-Б-5`): клиент пишет из кабинета, менеджер видит в том же диалоге, что и бот. Один экран «Мессенджеры» у сотрудника вместо трёх.
4. **Автоматизация слушает реестр событий уведомлений** (`Р-Б-6`) — один источник событий, ни одной новой точки вызова в бизнес-коде.
5. **KPI — обобщение `SalesTarget`**, а не вторая модель (`Р-Б-7`).
6. **Ничего не копировать из Битрикса «как есть»**: не заводим «дела», «активности», «бизнес-процессы» и «CRM-формы» как отдельные сущности — есть задачи, диалоги, правила и обращения.
7. **Очистку делать в конце**, отдельными маленькими PR, после утверждения списка заказчиком (`Р-Б-3`).
