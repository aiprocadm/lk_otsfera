# ADR 0004: 1С — источник истины по синхронизируемым заказам и оплатам

**Статус:** принято, 2026-05-21 (контракт интеграции; сверено с кодом 2026-06-06).

## Контекст

Кабинет синхронизируется с 1С (pull заказов, оплат, документов, контрагентов).
Нужно однозначное правило, чья цифра главная при расхождении.

## Решение

Для заказов, пришедших из 1С, **1С владеет данными**: суммы, статусы и даты
(`totalAmount`, `paidAmount`, `financialStatus`, `paidAt` и др.) перезаписываются
блоком `ownedBy1C` при каждой синхронизации и **локально не пересчитываются**.
Матчинг — по `externalId`; организация вне scope → skip с причиной в `SyncLog`.

## Последствия

- Локальные правки этих полей у 1С-заказов бессмысленны — их перетрёт следующий pull.
- Суммы заявки (Order из кабинета) — снимок на момент создания; это инвариант №9.
- Контракт API 1С зафиксирован отдельным документом и не меняется без встречи с IT 1С.
